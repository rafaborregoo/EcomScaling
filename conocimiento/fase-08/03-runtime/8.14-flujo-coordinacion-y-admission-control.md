# FASE 8 — EJECUCIÓN Y SUPERVISIÓN
## 8.14 — Flujo de coordinación y admission control

### Propósito

Este runtime decide si una intervención puede entrar en ejecución sin producir conflicto global.

---

## 1. Admission Flow

1. receive new intervention;
2. discover active/scheduled/recovering interventions;
3. inspect global state;
4. check scope overlap;
5. check resource overlap;
6. check goal compatibility;
7. check dependencies;
8. check shared guardrails;
9. check measurement interference;
10. check locks/reservations;
11. compute admission outcome;
12. execute / queue / merge / partition / preempt / escalate.

---

## 2. Active Intervention Discovery

Consultar qué está:

- active;
- scheduled;
- paused;
- recovering;
- queued.

---

## 3. Global Revalidation

Antes de commit:

- read global state;
- recalculate shared limits;
- re-check commitments.

---

## 4. Scope Overlap

Compute conceptually:

**scope A ∩ active scopes**

If empty:
- parallel candidate.

If partial/full:
- deeper analysis.

---

## 5. Resource Overlap

Check:

- budget;
- inventory;
- customer exposure;
- quota;
- operational capacity.

---

## 6. Goal Compatibility

Determine:

- same direction;
- complementary;
- conflicting;
- unknown.

---

## 7. Dependency Graph

If upstream incomplete:

- downstream waits.

---

## 8. Shared Guardrail Evaluation

Calculate aggregate effect before admission.

---

## 9. Measurement Interference

If causal attribution would be materially contaminated:

- serialize;
- partition;
- reserve experiment namespace.

---

## 10. Reservation

For shared capacity:

- check availability;
- reserve;
- prevent double allocation.

---

## 11. Lock Acquisition

Acquire minimum sufficient lock where required.

---

## 12. Lock Wait

If unavailable:

- enter WAITING_FOR_RESOURCE;
- do not mark failed.

---

## 13. Revalidate After Lock

After wait/acquisition:

- read state again;
- revalidate plan/readiness/scope/guardrails.

---

## 14. SAFE_PARALLEL

Allowed when:

- interaction low/known;
- resources sufficient;
- actions compatible;
- no critical measurement conflict.

---

## 15. SERIALIZE

Use when:

- actions non-commutative;
- same critical target;
- collision cost high.

---

## 16. QUEUE

Use when:

- valid intervention;
- resource/window not currently available.

---

## 17. PARTITION

Split:

- objects;
- markets;
- audiences;
- time;
- capabilities.

---

## 18. MERGE

Merge if:

- same intent;
- same target;
- compatible approvals;
- measurement goals compatible.

---

## 19. PREEMPT

If higher-priority work requires resource:

- safely pause lower-priority work;
- release necessary resource;
- revalidate preempted work later.

---

## 20. CANCEL

If intervention becomes:

- redundant;
- obsolete;
- superseded.

---

## 21. ESCALATE

Use when conflict cannot be resolved safely by policy.

---

## 22. Supersession

When new valid plan replaces old:

- mark old as superseded;
- block stale actions;
- set new authoritative version.

---

## 23. Duplicate Detection

Compare:

- intent;
- target;
- timeframe.

---

## 24. Event Ordering

Ignore stale events that would revive superseded/cancelled work.

---

## 25. Compare-and-Change

Before write:

- verify expected current state.

If changed:
- conflict;
- reconcile/replan.

---

## 26. Optimistic Coordination

Allow parallelism when conflict probability low.

Before commit:
- detect conflict.

---

## 27. Pessimistic Coordination

Reserve/lock before execution when conflict cost high.

---

## 28. Critical Section

Protect coupled mutation until coherent state reached.

---

## 29. Deadlock Detection

Detect:

- mutual waiting;
- no progress.

---

## 30. Deadlock Resolution

Possible:

- abort one;
- release resource;
- reorder;
- escalate.

---

## 31. Lock Ordering

Acquire shared resources in consistent order when policy uses multiple locks.

---

## 32. Livelock Detection

If agents repeatedly yield/adjust without progress:

- stop coordination loop;
- serialize or escalate.

---

## 33. Starvation Control

For noncritical queued work:

- consider aging;
- never override safety priority.

---

## 34. Portfolio Monitoring

Observe:

- aggregate spend;
- aggregate customer exposure;
- global stock impact;
- risk concentration;
- error rate;
- conflict rate;
- wait time.

---

## 35. Portfolio Safe Mode

If common-mode incident:

- reduce autonomy across affected agents;
- pause dependent interventions.

---

## 36. Recovery Priority

While recovery active:

- block incompatible optimization writes.

---

## 37. Human Ownership

When human takeover owns resource:

- block AI writes on affected scope.

---

## 38. Manual Change Reconciliation

After hand-back:

- re-read;
- compare;
- update plan.

---

## 39. Shared Change Journal

Record common timeline for shared resources.

---

## 40. Coordination Recheck

After A finishes and B was waiting:

- do not auto-start B;
- revalidate B.

---

## 41. Future Conflict Awareness

Before starting long task:

- inspect near-future reservations/scheduled work.

---

## 42. Scheduling

Balance:

- priority;
- deadline;
- resource;
- dependency;
- safety.

---

## 43. Unknown Interaction

If material interaction cannot be understood:

- serialize first occurrence;
- observe;
- learn compatibility later.

---

## 44. Final Flow

**NEW INTERVENTION → DISCOVER ACTIVE WORK → CHECK OVERLAP/RESOURCES/GOALS/DEPENDENCIES/GUARDRAILS → CONFLICT?**

If no:
- SAFE_PARALLEL.

If yes:
- PARTITION / SERIALIZE / QUEUE / MERGE / PREEMPT / CANCEL / ESCALATE.

Then:

**REVALIDATE BEFORE EXECUTION**
