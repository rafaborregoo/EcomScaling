## Conceptos clasificados en más de una capa

### Error / Failure / Incident Taxonomy
- RAG: semántica.
- Contracts: classification representation.
- Runtime: decision flow.
- Policies: allowed responses.
- Learning: classification quality.

### Severity
- RAG: dimensions.
- Contracts: representation.
- Runtime: assessment.
- Tenant: thresholds.
- Learning: calibration.

### Retryability
- RAG: principle.
- Contracts: property.
- Runtime: retry decision.
- Policies: verify-before-retry.
- Tenant: retry budget.
- Learning: effectiveness.

### Unknown Outcome
- RAG: explicit uncertainty.
- Contracts: state knowledge.
- Runtime: verify-first.
- Policies: not failure.
- Learning: observability weakness.

### Containment
- RAG: contain before root cause.
- Contracts: action/evidence.
- Runtime: incident flow.
- Policies: no optimization during critical incident.
- Tenant: preauthorized actions.
- Learning: effectiveness.

### Incident Lifecycle
- RAG: DETECTED→TRIAGED→CONTAINED→RECOVERING→RESOLVED→CLOSED.
- Contracts: states/evidence.
- Runtime: transitions.
- Policies: closure verification.
- Learning: duration/latency.

### Quarantine
- RAG: isolation concept.
- Contracts: representation.
- Runtime: action.
- Tenant: configurable policy.
- Learning: outcome.

### Trust Regression
- RAG: autonomy can decrease.
- Runtime: restrict capability/scope.
- Tenant: regression rules.
- Learning: evidence.

## Redundancia consolidada

El documento repite intencionalmente:

- blocked is not failed;
- degraded is not broken;
- unknown is not failure;
- retry only when safe;
- contain before diagnose;
- response must be proportional;
- severity is contextual;
- recovery is not root-cause resolution;
- evidence must be preserved;
- incident classification can change.

Estas ideas se consolidaron en `01-rag-produccion`.
