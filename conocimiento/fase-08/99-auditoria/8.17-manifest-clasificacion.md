## Conceptos multi-capa

### Event vs Notification
- RAG: semantic distinction.
- Contracts: materiality/type.
- Runtime: trigger classification.
- Policies: no firehose.
- Learning: alert volume/noise.
- Tenant: thresholds.

### Audience
- RAG: audience-aware principle.
- Contracts: intended audience.
- Runtime: rendering/routing.
- Policies: least necessary disclosure.
- Tenant: actual roles.

### Severity / Priority
- RAG: conceptual semantics.
- Contracts: representable state.
- Runtime: delivery intensity.
- Policies: proportionality.
- Tenant: mappings.
- Learning: calibration.

### Decision Request
- RAG: decision-ready communication.
- Contracts: decision/context/risk/recommendation.
- Runtime: delivery/acknowledgement.
- Policies: no ambiguous approval.
- Tenant: decision authority.
- Learning: decision latency/quality.

### Incident Communication
- RAG: impact + containment first.
- Contracts: incident package.
- Runtime: initial alert/updates/resolution.
- Policies: no speculation/no spam.
- Tenant: routing/cadence.
- Learning: timeliness.

### Recovery Reporting
- RAG: restored/pending/residual.
- Contracts: recovery state.
- Runtime: updates.
- Policies: no “fixed” before verification.
- Learning: quality.

### Closure Reporting
- RAG: execution vs business outcome.
- Contracts: closure report.
- Runtime: report generation.
- Policies: no false success.
- Tenant: recipients.
- Learning: closure quality.

### Communication Freshness
- RAG: stale-state risk.
- Contracts: timestamp/version.
- Runtime: refresh/expiry.
- Policies: no stale approvals.
- Learning: stale-message incidents.

### Deduplication / Correlation
- RAG: reduce noise while preserving meaning.
- Contracts: relation identity.
- Runtime: grouping/update.
- Policies: no notification storms.
- Learning: duplicate rate.

### Communication Auditability
- RAG: trust/traceability.
- Contracts: message history.
- Runtime: append corrections.
- Policies: no silent rewrite.
- Learning: quality measurement.

## Redundancia consolidada

El documento repite de forma útil:

- communication is part of execution;
- reporting is not logging;
- event is not notification;
- materiality should drive notification;
- same truth, different presentation;
- critical must stand out;
- no response is not approval;
- request is not result;
- unknowns must be explicit;
- actionability matters;
- reporting should answer what next;
- reporting must derive from current state;
- silence can be acceptable but must not hide risk;
- high autonomy requires better visibility.

Estas ideas se consolidaron en `01-rag-produccion`.
