# 6.00 — Evaluación post-intervención, evidencia y aprendizaje operacional

## Alcance

El framework 6.00 no define un sistema técnico de memoria, promoción de conocimiento, decay, almacenamiento de experiencias ni feedback loop automatizado.

Sí define conceptos que pertenecen a la capa de experience/learning:

- histórico propio;
- baseline;
- intervención;
- medición;
- comparación;
- evidencia;
- confianza;
- cohortes;
- experimentos;
- guardrails después de una intervención.

Este documento conserva únicamente esos elementos.

---

## 1. Historia propia como evidencia

El comportamiento histórico del ecommerce es una referencia central.

Comparaciones útiles incluyen:

- actual vs 30 días;
- actual vs 90 días;
- actual vs año anterior;
- temporada actual vs temporada equivalente;
- cohortes entre sí.

El histórico propio puede ser más informativo que un benchmark externo cuando el negocio tiene particularidades fuertes.

Esto convierte la experiencia acumulada del ecommerce en evidencia relevante para futuras interpretaciones.

El documento fuente no define cómo debe persistirse esa historia.

---

## 2. Evaluación de una intervención

Después de aplicar un playbook o intervención, la secuencia conceptual es:

`Baseline → Intervention → Measurement → Comparison`

La evaluación no debe limitarse a comprobar si la métrica objetivo subió.

Debe observar simultáneamente:

- objetivo principal;
- métricas de apoyo;
- guardrails.

---

## 3. Primary, supporting y guardrail metrics

Una arquitectura madura de evaluación puede distinguir:

### Primary metric

La métrica que expresa el resultado principal buscado.

### Supporting metrics

Las métricas que ayudan a explicar por qué cambió el resultado.

### Guardrail metrics

Las métricas que no deberían deteriorarse de forma inaceptable durante la intervención.

Un experimento no debe declararse ganador basándose en una única métrica cuando el sistema global empeora.

---

## 4. Evidencia frente a hipótesis

El aprendizaje útil exige separar:

- observación;
- hipótesis;
- evidencia;
- causalidad demostrada.

Una correlación temporal después de una intervención no basta para atribuirle causalidad.

Cambios simultáneos en tráfico, promociones, producto, inventario, temporada, campañas, precios o mix pueden explicar el resultado.

Por tanto, una experiencia debe interpretarse con el nivel de evidencia realmente disponible.

---

## 5. Confianza del aprendizaje

Las conclusiones derivadas de una experiencia pueden tener confianza:

### Alta

Datos suficientes, definición clara, comparación adecuada y desviación clara.

### Media

Existen señales razonables pero también explicaciones alternativas.

### Baja

Datos insuficientes, mala comparabilidad o incertidumbre elevada.

La confianza debe acompañar a la interpretación para evitar convertir una experiencia débil en una regla general.

---

## 6. Experimentos y cohortes

Cuando no existe benchmark externo, el ecommerce todavía puede aprender mediante:

- control vs variant;
- cohortes;
- histórico propio;
- descomposición del funnel;
- economics.

El framework reconoce estos mecanismos como referencias válidas para evaluar rendimiento.

---

## 7. Qué no define este bloque

El documento fuente no define:

- estructura de un experience record;
- IDs;
- almacenamiento;
- memoria de largo plazo;
- promotion rules;
- decay;
- weighting de experiencias;
- deduplicación;
- generalización automática entre tenants;
- criterios de conversión de experiencia a conocimiento RAG.

Cualquier diseño de esos mecanismos deberá realizarse en un artefacto específico posterior.
