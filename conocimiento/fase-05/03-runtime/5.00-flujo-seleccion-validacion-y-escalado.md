# FASE 5.00 — Flujo runtime de selección, validación y escalado de playbooks

## Alcance

Este documento extrae la secuencia operacional descrita conceptualmente por el corpus 5.00.

No define implementación, jobs, APIs, eventos técnicos ni persistencia.

---

## 1. Entrada del proceso

El flujo de playbooks comienza cuando existe un problema:

1. detectado;
2. diagnosticado;
3. asociado a una causa suficientemente plausible;
4. priorizado.

La entrada no debería ser una métrica aislada sin interpretación causal.

---

## 2. Secuencia operacional principal

### Paso 1 — Verificar integridad

Comprobar primero si:

- los datos son fiables;
- el tracking es utilizable;
- el sistema técnico funciona de forma suficientemente correcta.

Si la integridad falla, debe resolverse antes de tomar decisiones estratégicas basadas en datos dudosos.

### Paso 2 — Verificar supervivencia y estabilidad

Determinar si existen riesgos críticos de:

- liquidez;
- margen;
- stock;
- checkout;
- fulfillment;
- operación.

Si existen, estos riesgos preceden al crecimiento o al escalado.

### Paso 3 — Confirmar causa y restricción

Antes de elegir táctica:

- aislar la causa;
- identificar el cuello de botella;
- comprobar si el problema representa una restricción relevante del sistema.

No debe priorizarse una optimización local si existe una restricción global más importante.

### Paso 4 — Identificar familias de playbooks candidatas

A partir del problema y causa diagnosticados, identificar las intervenciones plausibles.

No seleccionar automáticamente una táctica por la métrica deteriorada.

### Paso 5 — Filtrar por aplicabilidad

Para cada candidato, comprobar:

- prerrequisitos;
- contraindicaciones;
- dependencias;
- madurez;
- recursos;
- capacidad operativa;
- economía del negocio.

Los candidatos que violen condiciones críticas deben descartarse o posponerse.

### Paso 6 — Evaluar impacto sistémico

Antes de ejecutar, considerar:

- qué puede mejorar;
- qué puede empeorar;
- qué trade-offs introduce;
- qué riesgos de segundo orden aparecen;
- qué otras intervenciones bloquea, refuerza, compensa o destruye.

### Paso 7 — Elegir la intervención mínima suficiente

Cuando exista incertidumbre, preferir una intervención que:

- ataque la causa;
- tenga exposición limitada;
- genere nueva información;
- limite riesgo;
- sea medible;
- pueda ampliarse posteriormente.

### Paso 8 — Definir hipótesis y validación

Antes de ejecutar deben quedar definidos conceptualmente:

- resultado esperado;
- mecanismo causal;
- leading indicators relevantes;
- lagging indicators relevantes;
- criterio de éxito;
- horizonte temporal;
- criterio de parada;
- rollback cuando sea posible.

### Paso 9 — Ejecutar la secuencia de intervención

Patrón general:

**estabilizar → aislar → corregir → validar → optimizar → escalar**

No todos los playbooks necesitan todas las etapas con la misma intensidad, pero el orden expresa una lógica de control de riesgo.

### Paso 10 — Observar resultados

Comparar la respuesta real con:

- hipótesis;
- métricas esperadas;
- criterios de éxito;
- trade-offs aceptables;
- riesgos previstos;
- efectos secundarios.

### Paso 11 — Decidir continuidad

Posibles estados conceptuales:

- detener por criterio de parada;
- hacer rollback;
- corregir ejecución;
- mantener exposición y seguir observando;
- optimizar;
- aumentar exposición;
- escalar.

El corpus no define nombres técnicos de estado.

### Paso 12 — Diferenciar fallo de estrategia y fallo de ejecución

Si el resultado no aparece, determinar si:

1. el mecanismo estratégico era incorrecto para ese contexto; o
2. el mecanismo era válido pero la implementación fue deficiente.

Esta distinción evita descartar un playbook por una mala ejecución o repetir una estrategia inaplicable.

### Paso 13 — Escalar con evidencia

El aumento de exposición sigue el patrón:

**hipótesis  
→ prueba pequeña  
→ señal positiva  
→ validación  
→ repetibilidad  
→ incremento de exposición  
→ escalado**

No se escala únicamente por convicción o por una métrica favorable aislada.

### Paso 14 — Enviar evidencia a aprendizaje

La evidencia generada debe quedar disponible para el sistema de experiencia/aprendizaje:

- contexto;
- intervención;
- resultados;
- trade-offs;
- failure modes;
- éxito o parada;
- señales de repetibilidad.

---

## 3. Orden de prioridad entre clases de intervención

El orden conceptual general es:

**integridad → supervivencia → estabilidad → eficiencia → crecimiento → escalado**

Esta secuencia actúa como regla de orquestación: una fase posterior no debería dominar mientras existan fallos críticos en una fase anterior.

---

## 4. Playbooks compuestos

Cuando el problema exige varias intervenciones:

1. identificar las dependencias entre ellas;
2. ordenar las intervenciones;
3. comprobar si una bloquea o habilita a otra;
4. mantener observabilidad suficiente;
5. evitar aumentar simultáneamente la exposición de múltiples cambios sin capacidad para interpretar el resultado.

Un playbook compuesto no equivale a ejecutar tácticas indiscriminadamente en paralelo.

---

## 5. Condiciones de salida

El proceso puede finalizar conceptualmente cuando:

- el problema original se ha corregido suficientemente;
- se ha alcanzado el criterio de éxito;
- se ha confirmado que la intervención no es adecuada;
- se ha activado un criterio de parada;
- una dependencia impide continuar;
- se requiere otra intervención previa;
- el sistema pasa de validación a optimización o escalado.

El documento fuente no define automatización de estas transiciones.
