# FASE 5.09 — Flujo runtime de validación de datos, causalidad y experimentación

## Alcance

Este artefacto recoge la lógica operacional explícita del corpus.

No define pipelines técnicos, jobs, APIs ni implementación estadística.

## 1. Entrada

Puede activarse ante:

- metric change;
- dashboards disagree;
- tracking issue;
- suspicious ROAS;
- CVR drop;
- CAC anomaly;
- LTV jump;
- experiment request;
- attribution uncertainty;
- insufficient evidence.

## 2. Paso 1 — Validar definición

Preguntar:

- ¿qué significa exactamente la métrica?;
- ¿cuál es su grain?;
- ¿qué denominator usa?;
- ¿incluye taxes?;
- ¿cómo trata refunds?;
- ¿qué currency usa?;
- ¿qué fecha representa?

## 3. Paso 2 — Validar fuente

Preguntar:

- ¿es la fuente adecuada para esta pregunta?;
- ¿existe source of truth más próximo al hecho?;
- ¿platform data está siendo confundido con business truth?

## 4. Paso 3 — Validar freshness y completeness

Comprobar:

- last update;
- missing data;
- event coverage;
- delayed data;
- impacted segments.

## 5. Paso 4 — Validar uniqueness y consistency

Comprobar:

- duplicates;
- deduplication;
- event ordering;
- schema changes;
- sessionization;
- identity issues.

## 6. Paso 5 — Reconciliar

Comparar sistemas relevantes.

Ejemplo:

**analytics ↔ ecommerce ↔ payments/finance**

Las diferencias deben ser explicables.

## 7. Paso 6 — Segmentar

Antes de interpretar un agregado:

- device;
- geo;
- channel;
- customer type;
- product;
- cohort;
- browser.

Comprobar mix effects y Simpson's paradox.

## 8. Paso 7 — Buscar eventos externos

Revisar:

- seasonality;
- campaigns;
- promotions;
- product launches;
- technical releases;
- business trend.

## 9. Paso 8 — Graduar confianza

Conceptualmente:

- high;
- medium;
- low.

La fuerza de la conclusión debe corresponder a la evidencia.

## 10. Paso 9 — Elegir acción proporcional

### Alta confianza
Puede justificar mayor exposición.

### Baja confianza
Preferir:

- smaller reversible action;
- information gathering;
- proxy;
- experiment;
- scenario.

## 11. Árbol de confianza del dato

Antes de usar una métrica:

1. ¿definición correcta?;
2. ¿fuente adecuada?;
3. ¿actualizada?;
4. ¿suficientemente completa?;
5. ¿duplicados controlados?;
6. ¿reconcilia razonablemente?;
7. ¿periodo comparable?

Solo entonces interpretar.

## 12. Árbol de causalidad

Ante:

> Después de X mejoró Y.

Preguntar:

- ¿existió control?;
- ¿había trend previo?;
- ¿hubo cambios simultáneos?;
- ¿seasonality?;
- ¿mix shift?;
- ¿mecanismo causal plausible?

A mayor incertidumbre, menor fuerza de conclusión.

## 13. Árbol de experimentación

Preguntar:

1. ¿existe problema/incertidumbre relevante?;
2. ¿puede formularse hipótesis falsable?;
3. ¿hay suficiente volumen?;
4. ¿intervención aislable?;
5. ¿primary metric y guardrails definidos?

Si sí:

→ experimentar.

Si no:

→ utilizar otro método de aprendizaje.

## 14. Fix vs Test

Si existe un fallo demostrado:

→ fix.

Si existe incertidumbre entre alternativas plausibles:

→ experiment.

## 15. Flujo experimental

1. formular hypothesis;
2. definir primary metric;
3. definir guardrails;
4. definir experiment unit;
5. definir treatment/control;
6. establecer contexto;
7. ejecutar;
8. comprobar implementation integrity;
9. analizar practical + statistical significance;
10. documentar learning;
11. rollout, iterate o rollback.

## 16. Validación de implementación experimental

Comprobar:

- sample ratio mismatch;
- contamination;
- interference;
- novelty;
- peak contamination;
- premature stopping.

## 17. Data Incident

Secuencia:

**detect  
→ contain  
→ identify scope  
→ fix  
→ backfill if possible  
→ document**

## 18. Tracking roto durante campaña

Prioridad:

1. confirmar alcance;
2. mantener transactional source;
3. evitar decisiones agresivas;
4. reparar;
5. reconstruir si es posible;
6. reevaluar campaña.

## 19. Dos dashboards no coinciden

Comparar:

- definition;
- timezone;
- attribution;
- refunds;
- currency;
- filters;
- freshness.

No elegir arbitrariamente una cifra.

## 20. Métrica cambia bruscamente

Secuencia:

1. tracking;
2. pipeline;
3. definition;
4. segmentation;
5. external events;
6. business diagnosis.

## 21. Resultados experimentales contradictorios

Revisar:

- AOV;
- mix;
- rollout;
- segments;
- novelty;
- external effects.

No elegir la señal favorable por conveniencia.

## 22. Salidas conceptuales

El runtime puede concluir:

- data trustworthy;
- metric definition issue;
- tracking issue;
- pipeline issue;
- reconciliation issue;
- identity issue;
- source mismatch;
- aggregation/mix issue;
- causal evidence weak;
- experiment viable;
- experiment not viable;
- more information required;
- small reversible intervention recommended;
- rollout justified;
- rollback/iterate required.

No se definen códigos técnicos.
