# FASE 5.08 — Contexto de tenant para operaciones, fulfillment y CX

## Propósito

Las recomendaciones de 5.08 dependen del modelo operativo real del ecommerce.

No deben inventarse valores.

## 1. Fulfillment Model

Puede ser necesario conocer:

- internal;
- 3PL;
- hybrid;
- warehouses;
- operating hours;
- cut-offs.

## 2. Order Flow

Puede incluir:

- validation;
- allocation;
- picking;
- packing;
- labeling;
- dispatch;
- carrier handoff;
- delivery.

## 3. Operational Times

Puede ser relevante:

- processing time;
- fulfillment time;
- transit time;
- order cycle time;
- return cycle time.

## 4. Service Promise

Puede incluir:

- promised delivery;
- SLA;
- cut-off;
- market-specific promise;
- service options.

## 5. Capacity

Puede ser necesario conocer:

- staffing;
- stations;
- equipment;
- warehouse space;
- systems;
- pickup capacity;
- utilization;
- backlog.

## 6. Carrier Context

Puede incluir:

- carrier mix;
- geography;
- rates;
- on-time performance;
- variability;
- damage;
- loss;
- tracking;
- support.

## 7. Order Quality

Puede ser relevante:

- order accuracy;
- picking errors;
- packing errors;
- damage rate;
- perfect order rate.

## 8. Packaging

Puede incluir:

- packaging type;
- cost;
- weight;
- volume;
- damage performance;
- sustainability constraints.

## 9. Returns

Puede ser necesario conocer:

- return rate;
- return reasons;
- reverse logistics;
- inspection time;
- restock rate;
- write-off;
- exchange/refund mix.

## 10. Support

Puede incluir:

- channels;
- agents;
- hours;
- contact rate;
- tickets/order;
- WISMO;
- first response;
- resolution time;
- first-contact resolution;
- escalation.

## 11. Customer Experience

Puede ser relevante:

- reviews;
- NPS;
- CSAT;
- CES;
- complaints;
- repeat;
- refund behavior;
- customer effort.

## 12. Economics

Puede incluir:

- cost/order;
- cost/ticket;
- shipping cost;
- fulfillment cost;
- return cost;
- compensation cost;
- cost-to-serve;
- contribution impact.

## 13. Automation and Systems

Puede ser necesario conocer:

- WMS;
- OMS;
- support tooling;
- automation;
- self-service;
- chatbots;
- integrations;
- system dependencies.

## 14. Incident and Continuity Context

Puede incluir:

- alternate carrier;
- alternate supplier;
- system redundancy;
- manual fallbacks;
- single points of failure.

## 15. International Operations

Puede ser relevante:

- countries;
- customs;
- duties;
- local carriers;
- local support;
- return method;
- promise by geo.

## 16. Peak Context

Puede incluir:

- launches;
- promotional calendar;
- seasonal peaks;
- expected demand;
- flexible capacity options.

## 17. Data Quality

Puede ser necesario conocer:

- timestamp completeness;
- ticket classification quality;
- carrier event reliability;
- order-status consistency;
- return-reason completeness.

## 18. Maturity

El ecommerce puede encontrarse en:

- inicial;
- tracción;
- crecimiento;
- escala.

La madurez condiciona complejidad operativa necesaria.

## 19. Restricciones que no deben asumirse

No inventar:

- SLA target;
- utilization target;
- backlog threshold;
- compensation policy;
- staffing level;
- carrier quality;
- 3PL pricing;
- return economics;
- support capacity;
- international readiness.
