# FASE 5.11 — Requisitos conceptuales del contrato de recovery, crisis y playbooks transversales

## Estado

Este artefacto define requisitos semánticos derivados del corpus 5.11.

No define schemas técnicos, APIs, tablas, thresholds ni estados de implementación obligatorios.

## 1. Crisis State

Debe poder representarse conceptualmente:

- normal;
- degraded;
- crisis;
- recovery;
- post-crisis normalization.

La fuente también propone estados conceptuales Green / Yellow / Red, pero sus thresholds concretos no están definidos.

## 2. Incident

Debe poder representar:

- incident type;
- detected_at;
- affected systems;
- blast radius;
- severity;
- urgency;
- reversibility;
- current status;
- owner;
- known facts;
- hypotheses;
- unknowns.

## 3. Blast Radius

Puede ser necesario comunicar:

- SKU;
- country;
- channel;
- browser/device;
- customer segment;
- whole store.

## 4. Severity

Debe poder representar factores como:

- Revenue affected;
- customers affected;
- cash impact;
- reputational risk;
- regulatory risk;
- irreversibility.

No se define scoring universal.

## 5. Crisis Confidence

Debe poder separar:

- confirmed;
- probable;
- unknown.

También debe permitir distinguir hecho observado de hipótesis causal.

## 6. Triage

Debe poder comunicar prioridad conceptual entre:

- safety/integrity;
- continuity;
- cash/economics;
- customer;
- operations;
- growth.

## 7. Containment Action

Puede ser necesario representar:

- action;
- scope;
- reversibility;
- reason;
- expected benefit;
- risk;
- owner;
- rollback condition.

## 8. Recovery Baseline

Debe poder representar qué condiciones definen recuperación:

- technical functionality;
- SLA;
- backlog;
- contribution;
- data integrity;
- customer impact.

## 9. Validation Window

Puede ser necesario indicar:

- start;
- duration/horizon;
- monitored metrics;
- relapse risk;
- stability status.

La fuente no define duración universal.

## 10. Exit Criteria

Debe poder representar:

- root cause controlled;
- critical metrics recovered;
- residual risk acceptable;
- follow-up established.

## 11. Decision Log

Debe poder registrar conceptualmente:

- decision;
- timestamp;
- rationale;
- evidence;
- owner;
- expected outcome;
- rollback;
- later result.

## 12. Root Cause

Debe poder distinguir:

- trigger;
- root cause;
- contributing factors;
- common cause;
- causal chain.

## 13. Recovery Plan

Puede ser necesario representar:

- containment;
- dependencies;
- parallel actions;
- critical path;
- stabilization;
- recovery;
- validation;
- rescaling.

## 14. Crisis Playbook

Debe poder comunicar:

- applicable condition;
- triage priority;
- containment;
- diagnostic steps;
- corrective action;
- preventive action;
- validation;
- exit criteria;
- learning.

## 15. Economic Crisis Context

Puede ser necesario representar:

- cash available;
- runway;
- obligations;
- inventory commitments;
- marketing spend;
- supplier payments;
- refunds;
- contribution;
- profitability.

## 16. Data Crisis Context

Puede ser necesario representar:

- trustworthy sources;
- broken sources;
- affected periods;
- reconstruction/backfill status;
- residual uncertainty.

## 17. Communication

Puede ser necesario distinguir:

- internal communication;
- external communication;
- affected audience;
- known facts;
- action required;
- promise certainty.

## 18. Workaround

Debe poder representar:

- temporary workaround;
- purpose;
- owner;
- risk;
- debt created;
- removal condition.

## 19. Post-Mortem

Puede ser necesario comunicar:

- what happened;
- impact;
- timeline;
- cause;
- response;
- what worked;
- what did not;
- prevention;
- playbook update.

## 20. Traceability

Debe poder relacionar:

**incident → evidence → decision → action → outcome → prevention**

## 21. No definido por la fuente

La fuente no define:

- JSON;
- DTOs;
- APIs;
- exact severity thresholds;
- exact Green/Yellow/Red thresholds;
- automated incident state machine;
- RBAC;
- approval matrix;
- exact escalation thresholds;
- exact cash runway trigger;
- automatic rollback;
- communication templates;
- incident tooling.

No deben inventarse.
