# FASE 5.08 — Experiencias operativas, incidentes y customer outcomes

## Alcance

Este documento separa el aprendizaje dinámico de los principios operativos estables.

La fuente describe qué debe aprender el sistema de la operación real, pero no define un motor técnico de learning.

## 1. Unidad de experiencia operacional

Una experiencia puede relacionar:

- order/process context;
- incident;
- stage;
- root cause;
- intervention;
- operational outcome;
- customer outcome;
- economic outcome;
- recurrence.

## 2. Aprendizaje de Delivery

Debe distinguir:

- processing delay;
- fulfillment delay;
- carrier delay;
- last-mile delay;
- promise mismatch.

Esto evita repetir diagnósticos superficiales.

## 3. Aprendizaje de Order Errors

Puede conservar patrones por:

- SKU;
- operator;
- warehouse location;
- process stage;
- period.

El objetivo es identificar recurrencias y causas sistémicas.

## 4. Aprendizaje de Damage

Puede relacionar:

- SKU;
- packaging;
- carrier;
- route;
- warehouse;
- handling.

## 5. Aprendizaje de Carrier Performance

Puede observar:

- on-time delivery;
- variability;
- damages;
- losses;
- tracking quality;
- support quality;
- total economic cost.

## 6. Aprendizaje de Capacity

Debe poder registrar:

- backlog;
- utilization;
- bottleneck;
- peak context;
- temporary vs structural nature;
- intervention;
- recovered throughput.

## 7. Aprendizaje de Support

Puede conservar:

- contact reason;
- tickets/order;
- WISMO;
- first response;
- resolution time;
- recontact;
- outcome.

## 8. Aprendizaje de Root Causes

Cada incidencia recurrente debería poder alimentar:

- qué ocurrió;
- dónde;
- causa;
- recurrence mechanism;
- preventive control.

## 9. Aprendizaje de Service Recovery

Puede observar impacto de:

- recognition;
- explanation;
- resolution;
- compensation;
- follow-up;

sobre:

- satisfaction;
- repeat;
- review;
- refund;
- retained relationship.

## 10. Aprendizaje de Returns

Puede distinguir:

- return reason;
- operational cost;
- reverse logistics time;
- exchange vs refund;
- restock success;
- write-off.

## 11. Aprendizaje de Self-Service y Automation

Debe poder observar:

- effort reduction;
- containment;
- escalation need;
- error rate;
- resolution quality;
- maintenance burden.

## 12. Aprendizaje de 3PL

Puede comparar:

- outsourced cost;
- internal benchmark;
- SLA;
- error;
- control;
- geography;
- growth capacity.

## 13. Aprendizaje de Incidents

Un post-mortem puede conservar:

- trigger;
- scope;
- containment;
- fallback;
- customer communication;
- recovery;
- prevention.

## 14. Aprendizaje de International Operations

Puede registrar diferencias por geo en:

- delivery reliability;
- customs;
- return cost;
- support;
- carrier quality;
- customer effort.

## 15. Leading vs Lagging

Leading:

- backlog;
- processing time;
- carrier delays;
- tickets/order.

Lagging:

- retention;
- reviews;
- refunds;
- customer profitability.

El sistema no debe declarar éxito estructural solo con señales tempranas.

## 16. Reutilización del aprendizaje

Los outcomes operativos pueden alimentar:

- marketing;
- inventory;
- product;
- finance;
- CRM;
- CX.

## 17. No definido por la fuente

No se definen:

- confidence scores;
- automated root-cause model;
- promotion/decay;
- learning weights;
- incident severity algorithm;
- cross-tenant learning;
- statistical thresholds;
- memory retention windows.
