# FASE 5.10 — Experiencias de constraints, scale tests y moving bottlenecks

## Alcance

Este documento separa el aprendizaje dinámico del conocimiento estable sobre escalabilidad.

La fuente define qué debería aprender el sistema tras escalar o eliminar restricciones, pero no un motor técnico de learning.

## 1. Unidad de experiencia de escalado

Una experiencia puede relacionar:

- constraint identificado;
- evidence;
- headroom;
- intervention;
- scale increment;
- guardrails;
- outcome;
- next bottleneck;
- learning.

## 2. Aprendizaje de Constraints

Debe poder conservar:

- constraint type;
- why it limited throughput;
- intervention used;
- whether constraint was actually relieved;
- what became limiting afterwards.

Esto es esencial para evitar repetir diagnósticos antiguos cuando el sistema ya cambió.

## 3. Moving Bottleneck History

El sistema puede aprender secuencias como:

**demand  
→ conversion  
→ inventory  
→ cash**

o cualquier otra observada.

No debe asumir que la misma secuencia se repetirá siempre.

## 4. Scale Test Learning

Cada scale test puede registrar:

- input increase;
- duration;
- marginal CAC;
- backlog;
- SLA;
- stock;
- support;
- cash;
- customer quality;
- final decision.

## 5. Aprendizaje de Headroom

Puede aprender cuánto headroom aparente terminó siendo realmente utilizable antes de deteriorar:

- operations;
- economics;
- CX;
- cash.

## 6. Aprendizaje de Capacity Cliffs

Debe poder registrar:

- threshold observed;
- leading signals;
- backlog/error response;
- mitigation;
- recovery.

## 7. Aprendizaje de Marginal Economics

Puede conservar cómo cambiaron:

- CAC;
- contribution;
- operating cost;
- complexity;

a medida que aumentó escala.

## 8. Aprendizaje de Scale Velocity

Debe observar si la misma escala final produjo resultados distintos según velocidad de crecimiento.

## 9. Aprendizaje de Premature Scaling

Puede conservar:

- resource added;
- expected need;
- actual utilization;
- cost;
- whether demand materialized;
- rollback or restructuring.

## 10. Aprendizaje de Under-Scaling

Puede registrar oportunidades perdidas cuando existían:

- demand;
- economics;
- capacity;
- cash;

pero no se aumentó exposición.

## 11. Aprendizaje Organizativo

Puede observar:

- approval latency;
- founder dependency;
- delegation;
- decision rights;
- process standardization;
- output impact.

## 12. Aprendizaje de Automation/Software

Debe conservar si la intervención:

- increased throughput;
- reduced errors;
- reduced latency;
- introduced maintenance;
- introduced complexity.

## 13. Aprendizaje de Growth Engines

Puede registrar:

- core engine;
- marginal saturation;
- adjacent engine tested;
- validation;
- cannibalization;
- resulting portfolio of engines.

## 14. Aprendizaje de Resilience

Puede observar outcomes de:

- redundancy;
- supplier alternatives;
- carrier alternatives;
- flexible capacity;
- single points of failure.

## 15. Forecast vs Reality

Antes de una expansión pueden existir escenarios:

- Base;
- Upside;
- Downside.

Después debe compararse:

- realized demand;
- realized capacity need;
- realized cash impact;
- realized risk.

## 16. Reversibility Learning

Puede aprender qué decisiones resultaron fáciles o costosas de revertir.

Esto puede mejorar futuras decisiones de escala bajo incertidumbre.

## 17. Guardrail Learning

Debe conservar qué métricas empezaron a deteriorarse antes del fracaso global.

Ejemplos:

- backlog;
- marginal CAC;
- support contacts;
- inventory coverage.

## 18. Learning from Next Bottleneck

Cada intervención relevante debería responder:

> ¿Qué se convirtió en el siguiente constraint?

Esta información alimenta diagnóstico futuro.

## 19. No definido por la fuente

No se definen:

- confidence scores;
- promotion/decay;
- automated bottleneck prediction model;
- cross-tenant learning;
- learning weights;
- causal graph;
- memory retention windows;
- automatic scale policy.

No deben inventarse.
