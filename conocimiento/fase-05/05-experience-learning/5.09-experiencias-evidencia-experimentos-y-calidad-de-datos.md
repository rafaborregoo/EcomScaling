# FASE 5.09 — Experiencias, evidencia, experimentos y calidad de datos

## Alcance

Este documento separa aprendizaje dinámico del conocimiento estable sobre datos y experimentación.

La fuente define qué debería conservarse como experiencia, pero no un motor técnico de learning.

## 1. Unidad de experiencia de datos

Una experiencia puede relacionar:

- business question;
- metric;
- source;
- quality state;
- anomaly;
- diagnosis;
- action;
- outcome;
- learning.

## 2. Aprendizaje de Tracking

Puede conservar:

- event affected;
- missing/duplicate state;
- platform/device;
- root cause;
- correction;
- backfill status;
- recurrence.

## 3. Aprendizaje de Reconciliation

Debe poder registrar:

- systems compared;
- expected difference;
- observed difference;
- explanation;
- unresolved gap.

Esto ayuda a distinguir discrepancias normales de fallos reales.

## 4. Aprendizaje de Data Incidents

Un incidente puede conservar:

- trigger;
- affected period;
- affected metrics;
- scope;
- containment;
- fix;
- backfill;
- residual uncertainty.

## 5. Aprendizaje de Metric Definitions

Cuando una definición cambia, debe conservarse:

- old version;
- new version;
- effective date;
- historical comparability;
- metric break.

## 6. Aprendizaje de Identity Resolution

Puede observar impacto de:

- duplicates;
- guest checkout;
- multiple emails;
- customer_id quality;
- identity gaps;

sobre:

- new customer count;
- repeat rate;
- LTV.

## 7. Aprendizaje Experimental

Cada experimento debería conservar:

- experiment_id;
- hypothesis;
- treatment;
- control;
- primary metric;
- guardrails;
- duration;
- result;
- context;
- learning.

## 8. Tests ganadores y perdedores

El aprendizaje debe conservar ambos.

Un losing test puede:

- descartar hipótesis;
- reducir incertidumbre;
- evitar inversión mayor.

## 9. Learning Value

Además del impacto económico inmediato, puede conservarse cuánto conocimiento produjo el test sobre una incertidumbre estratégica.

## 10. Aprendizaje de Causalidad

Debe distinguirse el tipo de evidencia:

- correlation;
- pre/post;
- observational;
- controlled experiment;
- geo/matched-market;
- triangulated evidence.

No debe promoverse una correlación automáticamente a hecho causal.

## 11. Forecast de confianza

La experiencia puede mostrar cuándo conclusiones de:

- high confidence;
- medium confidence;
- low confidence;

resultaron más o menos fiables.

La fuente no define score numérico.

## 12. Leading vs Lagging Outcomes

Debe conservarse qué señales eran tempranas y qué resultados finales aparecieron después.

Ejemplo:

**CTR → CVR → Contribution → Repeat → LTV**

## 13. Proxy Learning

Cuando se utilizó un proxy debe registrarse:

- proxy used;
- final outcome cuando madure;
- relación observada entre ambos.

Esto evita tratar proxies como outcomes permanentes.

## 14. Segment Learning

Debe conservar contexto de:

- device;
- channel;
- geo;
- cohort;
- product;
- customer type.

Los promedios agregados pueden ocultar resultados opuestos.

## 15. Learning from Contradictions

Cuando fuentes o métricas discrepan, documentar:

- discrepancy;
- definitions;
- root cause;
- chosen source;
- residual uncertainty.

## 16. Experiment Registry como memoria

El registro evita:

- repetir tests;
- perder hipótesis;
- olvidar contexto;
- publication bias.

## 17. Recommendation Outcome Traceability

El aprendizaje ideal conecta:

**data  
→ signal  
→ diagnosis  
→ priority  
→ recommendation  
→ action  
→ experiment/outcome**

## 18. Reutilización

Este aprendizaje puede alimentar:

- diagnosis;
- prioritization;
- playbook selection;
- recommendation engine;
- future experiment design.

## 19. No definido por la fuente

No se definen:

- confidence scores numéricos;
- promotion/decay;
- automated causal graph;
- memory weighting;
- cross-tenant generalization;
- Bayesian updating;
- automated policy learning;
- exact statistical thresholds.
