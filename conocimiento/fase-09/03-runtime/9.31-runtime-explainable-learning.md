# 9.31 — Runtime de Explainable Learning

## Objetivo

Definir cuándo y cómo generar explicaciones durante uso del Learning Engine.

## 1. Explanation Trigger

Generar explicación cuando:

- learning afecta recomendación;
- confidence cambia materialmente;
- knowledge se promociona;
- knowledge se rechaza;
- contradiction se resuelve;
- supersession ocurre;
- human review es requerida.

## 2. Evidence Retrieval

Recuperar:

- supporting evidence;
- counterevidence;
- context;
- provenance;
- current version.

## 3. Rationale Construction

Construir explanation usando:

- claim;
- evidence;
- confidence factors;
- assumptions;
- uncertainty;
- limits.

## 4. Audience Adaptation

Adaptar profundidad a:

- business user;
- expert;
- auditor;
- operator.

## 5. Faithfulness Gate

Verificar que:

- cada reason está respaldada;
- no se inventan factores;
- la version es correcta;
- counterevidence relevante está incluida.

## 6. Stale Explanation Gate

Si knowledge cambió:

- invalidar explanation antigua;
- regenerar versión.

## 7. Abstention Explanation

Si no puede concluirse:

- explicar por qué;
- indicar missing evidence;
- indicar siguiente condición necesaria.

## 8. Audit Mode

Debe permitir explicación más detallada con:

- provenance;
- lineage;
- transitions;
- reviewer.

## Regla runtime

> Explain only what the system can trace.
