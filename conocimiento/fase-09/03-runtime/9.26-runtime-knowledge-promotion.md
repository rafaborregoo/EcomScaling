# 9.26 — Runtime de Knowledge Promotion

## Objetivo

Definir cómo detectar candidates, evaluar gates y ejecutar promotion transitions.

## 1. Candidate Detection

Generar candidate cuando exista:

- repeated evidence;
- stable pattern;
- high reuse potential;
- validated tenant learning;
- cross-tenant consistency.

## 2. Target Selection

Determinar si corresponde a:

- tenant;
- cohort;
- global;
- playbook;
- benchmark;
- RAG;
- governance review.

## 3. Evidence Gate

Comprobar:

- strength;
- independence;
- maturity;
- attribution;
- stability.

## 4. Context Gate

Verificar:

- scope;
- conditions;
- exceptions;
- generalization limits.

## 5. Contradiction Gate

Si existe contradiction fuerte:

- no promover globalmente;
- contextualizar;
- fragmentar;
- mantener candidate.

## 6. Risk Gate

Si la knowledge puede afectar high-impact decisions:

- requerir review;
- elevar threshold.

## 7. Review

Cuando corresponda:

- solicitar human/governance review;
- registrar decisión;
- registrar rationale.

## 8. Promotion

Al aprobar:

- crear nueva version;
- conservar source;
- asignar scope;
- actualizar status.

## 9. Rejection

Si se rechaza:

- conservar candidate;
- registrar reason;
- permitir nueva evaluación futura.

## 10. Reversal

Si nueva evidencia degrada knowledge:

- reduce scope;
- degrade;
- supersede;
- withdraw;
- invalidate.

## Regla runtime

> Promotion must increase reuse without increasing epistemic overconfidence.
