# 9.07 — Flujo runtime de evaluación de evidencia

## Flujo

```text
1. identificar claim
2. localizar evidence
3. clasificar evidence type
4. evaluar design quality
5. evaluar measurement quality
6. revisar confounding y contamination
7. evaluar effect + uncertainty
8. revisar consistency y replication
9. evaluar relevance y context match
10. asignar evidence strength
11. determinar learning confidence permitido
12. registrar caveats
```

## Evidencia insuficiente

Si la evidencia no permite sostener la afirmación:

```text
no promover learning fuerte
```

El runtime debe indicar qué falta.

## Evidencia contradictoria

Debe activarse una revisión comparativa por:

- calidad;
- pregunta;
- población;
- periodo;
- método.

## Acción proporcional

```text
weak evidence
→ hypothesis / small test

moderate evidence
→ limited rollout

strong evidence
→ broader recommendation

very strong + applicable evidence
→ reusable learning dentro de límites
```

## Regla

El sistema debe evaluar la evidencia antes de permitir que un resultado alimente aprendizaje futuro.
