# 9.33 — Runtime de Forgetting, Invalidation y Withdrawal

## Objetivo

Definir cómo retirar knowledge de forma segura y consistente.

## 1. Trigger

Puede activarse por:

- invalidation;
- supersession;
- expiry;
- obsolescence;
- privacy/legal requirement;
- governance decision.

## 2. Scope Evaluation

Antes de retirar:

- identificar affected scope;
- distinguir local vs global;
- comprobar successors;
- comprobar dependencias.

## 3. Invalidation Gate

Si se pretende invalidar:

- exigir evidence;
- registrar reason;
- revisar provenance;
- determinar affected claims.

## 4. Withdrawal Action

Actualizar estado:

- active → archived;
- active → withdrawn;
- active → invalidated;
- dormant → archived;
- etc.

## 5. Retrieval Cleanup

Retirar del path operativo:

- RAG;
- indexes;
- recommendation stores;
- active playbooks.

## 6. Derived Cleanup

Buscar:

- caches;
- summaries;
- embeddings;
- derived knowledge;
- precomputed outputs.

## 7. Impact Review

Marcar dependientes para:

- review;
- degradation;
- recomputation;
- withdrawal.

## 8. Tombstone Creation

Conservar registro mínimo de existencia y retirada.

## 9. Reinstatement

Si procede:

- abrir review;
- revalidar;
- crear nueva version;
- restaurar solo scope autorizado.

## Regla runtime

> Withdrawal is complete only when active influence has actually stopped.
