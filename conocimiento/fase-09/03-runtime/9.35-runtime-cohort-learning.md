# 9.35 — Runtime de Cohort Learning

## Objetivo

Definir cómo formar, validar, actualizar y usar cohortes durante learning.

## 1. Cohort Candidate Detection

Puede surgir cuando:

- multiple tenants share pattern;
- transfer works repeatedly;
- global contradictions cluster;
- hidden variables appear.

## 2. Membership Evaluation

Comparar tenant con dimensiones relevantes.

## 3. Evidence Gate

Comprobar:

- tenant independence;
- support;
- variance;
- contradictions;
- maturity.

## 4. Activation

Activar cohort knowledge cuando:

- definition es clara;
- evidence suficiente;
- pattern estable;
- privacy constraints satisfechas.

## 5. Usage

Al usar cohort knowledge:

- aplicarlo como prior;
- combinar con local evidence;
- reducir weight si tenant mismatch aumenta.

## 6. Splitting

Si variance o contradictions aumentan:

- buscar hidden variable;
- proponer subcohorts;
- re-evaluar patterns.

## 7. Merging

Si differences pierden valor:

- simplificar cohort structure;
- conservar lineage.

## 8. Drift Review

Revisar:

- membership;
- behavior;
- temporal validity.

## 9. Promotion

Cohort knowledge puede alimentar:

- transfer learning;
- benchmark candidates;
- playbook candidates;
- global knowledge candidates.

No debe promoverse automáticamente.

## Regla runtime

> Use cohorts to refine priors, not to override tenant evidence.
