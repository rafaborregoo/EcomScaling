# 9.13 — Flujo runtime post-incidente

## Flujo

```text
1. detectar anomalía o incidente
2. clasificar tipo
3. evaluar severity y blast radius
4. contener
5. decidir rollback / stop / escalation
6. recuperar
7. identificar residual effects
8. proteger datos contaminados
9. reconstruir expected vs actual
10. analizar trigger y root cause
11. identificar contributing factors
12. generar corrective learning
13. generar preventive learning
14. revisar autonomía / policies / runtime
15. registrar recurrence checks
```

## Prioridad

Durante un incidente activo:

```text
SAFETY
>
LEARNING
```

Primero contener y recuperar.

Después analizar.

## Regla

El runtime no debe modificar automáticamente policies críticas basándose en una causa aún no confirmada.
