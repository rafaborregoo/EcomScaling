# 9.22 — Runtime de contradicciones entre aprendizajes

## Objetivo

Definir cómo detectar y tratar contradicciones durante razonamiento y actualización de knowledge.

## 1. Detection

Ante un nuevo learning:

1. identificar claims existentes relacionados;
2. comparar scope;
3. comparar contexto;
4. comparar temporalidad;
5. comparar métricas;
6. comparar direction/magnitude;
7. detectar overlap;
8. clasificar contradicción.

## 2. Apparent contradiction gate

Antes de marcar conflicto real:

- comprobar definiciones;
- normalizar métricas;
- comparar ventanas;
- revisar attribution;
- validar calidad de datos.

## 3. Context split

Si el conflicto se explica por contexto:

- fragmentar;
- crear applicability conditions;
- preservar ambos claims.

## 4. Evidence comparison

Si el contexto es equivalente:

- comparar evidence strength;
- independence;
- recency;
- coverage;
- confidence;
- attribution quality.

## 5. Unresolved state

Si no existe evidencia suficiente:

- no elegir arbitrariamente;
- mantener contradiction state;
- reducir confidence;
- solicitar más evidencia.

## 6. Policy conflict

Si un learning contradice policy:

- no modificar policy;
- registrar conflicto;
- escalar a governance.

## 7. Global vs tenant

Si learning local contradice global:

- mantener global;
- aplicar excepción local si está soportada;
- reducir applicability del global para ese tenant.

## 8. Supersession

Solo cuando exista evidence suficiente:

- marcar claim anterior como superseded;
- mantener histórico;
- activar nuevo scope.

## 9. Invalidation

Invalidar únicamente si:

- evidencia original era defectuosa;
- el claim deja de estar soportado;
- existía error de medición o inferencia.

## 10. Runtime usage

Cuando exista contradicción unresolved:

- evitar recomendaciones categóricas;
- explicitar uncertainty;
- preferir acciones reversibles;
- solicitar validación adicional.

## Regla runtime

> Never hide unresolved learning conflict behind a single confidence score.
