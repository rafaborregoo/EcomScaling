# 9.23 — Runtime de decay, obsolescencia y drift

## Objetivo

Definir cómo debe evaluar el sistema la vigencia temporal de un learning antes de utilizarlo.

## 1. Pre-use evaluation

Antes de usar un learning:

1. comprobar estado temporal;
2. revisar last validation;
3. comprobar stability profile;
4. verificar contexto actual;
5. buscar structural breaks;
6. buscar drift signals;
7. revisar contradicciones recientes;
8. estimar vigencia.

## 2. Freshness gate

Si el learning está stale:

- reducir confidence;
- buscar evidencia reciente;
- limitar uso;
- solicitar revalidación si el impacto es alto.

## 3. Structural break gate

Si existe cambio estructural:

- no asumir transferibilidad;
- marcar revalidation required;
- limitar uso hasta nueva evidencia.

## 4. Drift detection

Durante operación:

- observar cambios en outcomes;
- repetibilidad;
- variance;
- cohorts;
- channels;
- tools;
- data distributions.

## 5. Drift response

### Bajo
Mantener con observación.

### Medio
Reducir confidence o restringir scope.

### Alto
Suspender, revalidar o supersede.

## 6. Obsolescence

Si la condición original dejó de existir:

- impedir uso operacional;
- conservar histórico;
- registrar reason.

## 7. Seasonality

Si el learning es estacional:

- no degradarlo por ausencia fuera de temporada;
- activar según contexto temporal.

## 8. Dormancy

Un learning dormant puede reactivarse si:

- vuelve el contexto;
- no existe contraindicación;
- la infraestructura sigue siendo compatible.

## 9. Revalidation

Puede:

- confirmar;
- degradar;
- contextualizar;
- supersede;
- invalidate.

## 10. Runtime principle

> El uso de learning histórico debe depender de su vigencia contextual, no solo de su existencia.
