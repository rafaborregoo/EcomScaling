# 9.28 — Runtime de Anti-Learning

## Objetivo

Definir cómo filtrar evidencia antes de convertir experiencia en learning.

## 1. Data Quality Gate

Antes de evaluar learning:

- comprobar completeness;
- consistency;
- freshness;
- metric definitions;
- provenance.

## 2. Execution Gate

Verificar:

- qué se ejecutó;
- cuánto;
- con qué modificaciones;
- si hubo fallos.

## 3. Outcome Gate

Comprobar:

- maturity;
- objective alignment;
- side effects;
- measurement validity.

## 4. Attribution Gate

Evaluar:

- confounders;
- concurrent interventions;
- counterfactual plausibility;
- causal uncertainty.

## 5. Bias Gate

Buscar:

- selection;
- survivorship;
- confirmation;
- aggregation;
- feedback bias.

## 6. Contradiction Search

Antes de promover:

- buscar counterexamples;
- segmentar;
- revisar periods;
- revisar cohorts.

## 7. Decision

El runtime puede:

- validate;
- reduce confidence;
- quarantine;
- reject;
- abstain;
- request more evidence.

## 8. Promotion Veto

Bloquear promotion si:

- data corrupted;
- provenance unknown;
- execution unverified;
- severe contradiction unresolved.

## 9. Re-evaluation

Quarantined learning puede reabrirse cuando llega nueva evidencia.

## Regla runtime

> If the evidence chain is weak, weaken the conclusion before strengthening the story.
