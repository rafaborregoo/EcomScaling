# 9.36 — Runtime de Global Knowledge vs Tenant-Specific Learning

## Objetivo

Definir cómo combinar knowledge global, cohort y tenant-specific durante reasoning.

## 1. Context Resolution

Antes de retrieval:

- identificar tenant;
- business context;
- objective;
- channel;
- maturity;
- temporal state.

## 2. Layered Retrieval

Recuperar:

1. relevant policies;
2. tenant knowledge;
3. cohort knowledge;
4. global knowledge.

## 3. Applicability Gate

Para cada claim:

- comprobar scope;
- recency;
- confidence;
- context match;
- contradictions.

## 4. Conflict Resolution

Si global y local chocan:

- evaluar evidence;
- comprobar hidden variables;
- revisar execution;
- mantener exception si procede;
- escalar si unresolved y high-impact.

## 5. Cold Start

Si local evidence es baja:

- aumentar peso de global/cohort priors;
- mantener uncertainty;
- recomendar validation.

## 6. Mature Tenant

Si local evidence es fuerte:

- priorizar local applicability;
- mantener global framework como referencia.

## 7. Promotion Candidate

Si local pattern se repite cross-tenant:

- generar cohort/global candidate;
- no promover automáticamente.

## 8. Isolation Gate

Bloquear raw knowledge de otros tenants.

## Regla runtime

> Retrieve globally, reason contextually, decide locally.
