# 9.37 — Runtime de privacidad, aislamiento y aprendizaje

## Objetivo

Definir cómo aplicar isolation y privacy controls durante retrieval y learning.

## 1. Scope Resolution

Antes de acceder a knowledge:

- identificar tenant;
- user/agent role;
- purpose;
- allowed layer.

## 2. Access Gate

Filtrar por:

- ownership;
- sensitivity;
- permissions;
- purpose.

## 3. Retrieval

Solo después del access gate:

- semantic ranking;
- relevance;
- recency;
- confidence.

## 4. Cross-Tenant Learning Gate

Antes de agregar:

- comprobar transfer eligibility;
- sensitivity;
- abstraction;
- cohort size;
- re-identification risk.

## 5. Promotion

Tenant learning puede ascender a cohort/global solo si:

- privacy-safe;
- sufficiently abstract;
- evidence sufficient;
- governance approved cuando aplique.

## 6. Explanation Gate

Antes de mostrar rationale:

- eliminar tenant-identifying details;
- comprobar benchmark leakage;
- respetar audience permission.

## 7. Deletion Propagation

Ante deletion/retention trigger:

- localizar source;
- derived artifacts;
- embeddings;
- caches;
- learning objects;
- actualizar states.

## 8. Incident Handling

Si se detecta leakage:

- block access;
- identify affected artifacts;
- invalidate caches;
- log incident;
- escalate.

## Regla runtime

> Enforce privacy before retrieval, aggregation, promotion and explanation.
