# 9.16 — Flujo runtime de aprendizaje sobre priorización

## Flujo

```text
1. identificar problema priorizado
2. registrar alternatives
3. estimar impact / urgency / constraint
4. identificar bottleneck hypothesis
5. revisar dependencies
6. ejecutar acción seleccionada
7. medir outcome
8. calcular remaining gap
9. detectar nuevo bottleneck
10. evaluar opportunity cost
11. clasificar prioritization quality
12. actualizar calibración
13. repriorizar si procede
```

## Repriorización

Debe activarse cuando:

- cambia constraint;
- cambia urgency;
- se cierra gap;
- aparece nueva evidencia;
- cambia capacidad;
- aparece bottleneck más importante.

## Regla

El runtime debe evitar tanto mantener prioridades obsoletas como cambiar prioridades ante señales débiles sin relevancia material.
