# 9.27 — Runtime de Knowledge Contradiction y Supersession

## Objetivo

Definir cómo detectar conflicto y ejecutar reemplazo controlado.

## 1. Conflict Detection

Cuando entra nueva evidencia:

1. identificar knowledge relacionado;
2. comparar scope;
3. comparar outcomes;
4. evaluar contradiction;
5. medir overlap.

## 2. Resolution Gate

Decidir si corresponde:

- coexistence;
- contextualization;
- degradation;
- supersession;
- invalidation.

## 3. Supersession Gate

Exigir:

- evidence suficiente;
- scope claro;
- lineage;
- versioning;
- review si aplica.

## 4. Partial Supersession

Si el conflicto es localizado:

- limitar scope;
- mantener predecessor activo fuera del área afectada.

## 5. Activation

Al aprobar successor:

- marcar nueva versión active;
- actualizar predecessor;
- registrar effective date.

## 6. Retrieval Update

Actualizar retrieval para:

- priorizar active;
- excluir superseded operacionalmente;
- conservar historical access.

## 7. Rollback

Si successor falla:

- degradar;
- reactivar predecessor;
- registrar reason.

## 8. Policy Conflict

Si knowledge contradice policy:

- no supersede policy;
- escalar a governance.

## Regla runtime

> Replace knowledge only when evidence, scope and lineage are all explicit.
