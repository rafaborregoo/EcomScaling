# 9.29 — Runtime de Feedback Loops peligrosos

## Objetivo

Definir cómo detectar amplification y activar estabilización durante operación.

## 1. Monitor

Observar:

- exposure;
- allocation;
- concentration;
- diversity;
- performance;
- secondary outcomes;
- exploration share.

## 2. Amplification Detection

Detectar si:

- allocation growth aumenta;
- confidence crece con exposure;
- alternatives pierden observación;
- recommendations se concentran.

## 3. Exposure Correction

Antes de aumentar confidence:

- ajustar interpretación por exposure;
- revisar independence;
- revisar coverage.

## 4. Concentration Gate

Si concentration supera límites:

- reducir allocation growth;
- mantener exploration;
- pedir review.

## 5. Secondary Outcome Gate

Si métricas secundarias degradan:

- reducir amplification;
- detener scaling;
- re-evaluar objective.

## 6. Circuit Breaker

Activar si:

- runaway behavior;
- financial risk;
- anomalía severa;
- externality significativa.

## 7. Holdout Preservation

Cuando sea necesario:

- mantener grupo comparador;
- preservar counterfactual evidence.

## 8. Autonomy Loop

Si mayor autonomía genera más evidence de autonomía:

- no ampliar permisos automáticamente;
- escalar a governance.

## 9. Recovery

Tras frenar loop:

- evaluar daño;
- recalibrar;
- reintroducir exploration;
- actualizar learning.

## Regla runtime

> Never let the system use its own increased exposure as sufficient proof that more exposure is justified.
