# 9.21 — Runtime de Pattern Detection

## Objetivo

Definir cómo debe comportarse el sistema al detectar, validar y actualizar patrones durante operación.

## 1. Candidate generation

Cuando aparezca una regularidad:

1. identificar observaciones relacionadas;
2. construir pattern candidate;
3. delimitar contexto;
4. calcular support;
5. estimar coverage;
6. evaluar independencia;
7. buscar evidencia contradictoria;
8. identificar posibles confounders;
9. estimar stability;
10. asignar estado candidate.

## 2. Validation gate

No promocionar si:

- support insuficiente;
- observaciones altamente correlacionadas;
- contexto ambiguo;
- contradicciones graves;
- medición deficiente;
- efecto inestable.

## 3. Segmentation

Antes de promediar:

- segmentar por tenant;
- canal;
- cohorte;
- periodo;
- tipo de intervención;
- contexto operativo.

Si el patrón cambia de dirección, debe fragmentarse.

## 4. Sequence evaluation

Para secuencias:

- confirmar orden;
- registrar prerequisites;
- identificar pasos omitidos;
- diferenciar secuencia completa de parcial;
- observar failure points.

## 5. Contradiction search

Cada candidate debe buscar activamente:

- contraejemplos;
- excepciones;
- outcomes opuestos;
- contextos de fallo.

## 6. Promotion

Puede promocionarse cuando cumple criterios suficientes de:

- support;
- coverage;
- independencia;
- estabilidad;
- context definition;
- contradiction handling.

## 7. Degradation

Debe degradarse cuando:

- disminuye repetibilidad;
- aumenta contradicción;
- aparece drift;
- cambia el contexto;
- deja de reproducirse.

## 8. Invalidation

Puede invalidarse si:

- el efecto desaparece;
- estaba causado por medición defectuosa;
- existía confounder dominante;
- el contexto original dejó de existir.

## 9. Runtime usage

Los patterns pueden:

- informar recomendaciones;
- ajustar priorización;
- sugerir playbooks;
- disparar investigación;
- elevar riesgos.

No deben automáticamente:

- cambiar policies;
- crear permisos;
- convertirse en reglas obligatorias.

## 10. Regla runtime

> Detectar una regularidad es el inicio del aprendizaje, no su conclusión.
