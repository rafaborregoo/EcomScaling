# 9.27 — Experience / Learning de Supersession

## Objetivo

Conservar cómo el conocimiento cambia de una versión a otra.

## 1. Conflict History

Debe registrar:

- conflicting claims;
- context;
- evidence;
- severity;
- resolution.

## 2. Supersession History

Debe conservar:

- predecessor;
- successor;
- reason;
- scope;
- effective period;
- reviewer.

## 3. Rollback History

Debe registrar:

- failed successor;
- reactivation;
- reason;
- outcome.

## 4. Supersession Calibration

El sistema puede aprender:

- cuándo se supersede demasiado pronto;
- cuándo se mantiene conocimiento obsoleto demasiado tiempo;
- qué domains requieren más review.

## 5. Contextual Recurrence

Puede aprender que ciertas supersessions son:

- tenant-specific;
- channel-specific;
- temporal;
- structural.

## Regla

El Learning Engine debe aprender también de cómo evoluciona y reemplaza su propio conocimiento.
