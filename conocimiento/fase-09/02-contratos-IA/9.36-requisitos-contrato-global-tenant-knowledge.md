# 9.36 — Requisitos conceptuales de contrato para Global Knowledge vs Tenant-Specific Learning

## Objetivo

Definir qué información debe poder representarse para diferenciar y combinar knowledge por scope.

## 1. Knowledge Layer

Debe representar:

- global;
- cohort;
- tenant;
- policy;
- experience.

## 2. Scope

Debe incluir:

- tenant;
- cohort;
- market;
- channel;
- temporal validity;
- use-case.

## 3. Applicability

Debe representar:

- conditions;
- exclusions;
- context match;
- confidence.

## 4. Evidence Basis

Debe distinguir:

- global evidence;
- cohort evidence;
- local evidence;
- expert knowledge.

## 5. Override Relation

Debe incluir:

- base knowledge;
- local override;
- reason;
- scope;
- evidence;
- expiry/review state.

## 6. Contradiction Relation

Debe representar conflicts entre layers.

## 7. Retrieval Metadata

Debe permitir:

- source layer;
- active status;
- recency;
- priority;
- exclusion reason.

## 8. Promotion Path

Debe enlazar:

- tenant learning;
- cohort candidate;
- global candidate;
- review state.

## 9. Tenant Isolation

Debe impedir acceso cruzado a raw tenant learning.

## 10. Provenance

Debe conservar origen y transformaciones.

## Regla crítica

El contrato debe impedir que knowledge tenant-specific pierda su scope durante retrieval o promoción.
