# 9.34 — Requisitos conceptuales de contrato para Transfer Learning

## Objetivo

Definir qué información debe poder representarse para evaluar transferencia entre tiendas.

## 1. Source Learning

Debe representar:

- learning id;
- source scope;
- evidence strength;
- context;
- mechanism;
- applicability;
- limitations.

## 2. Target Context

Debe incluir dimensiones relevantes:

- business model;
- maturity;
- economics;
- channels;
- geography;
- category;
- operations;
- data quality.

## 3. Transfer Candidate

Debe representar:

- source learning;
- target;
- transfer class;
- expected applicability;
- required adaptation.

## 4. Similarity Assessment

Debe incluir:

- matching dimensions;
- mismatching dimensions;
- relevance of each dimension.

## 5. Transfer Confidence

Debe distinguir:

- source confidence;
- similarity confidence;
- transfer confidence;
- local confirmation confidence.

## 6. Validation Plan

Debe poder expresar:

- pilot;
- exposure;
- metrics;
- maturity window;
- stop conditions.

## 7. Transfer Outcome

Debe representar:

- positive transfer;
- neutral;
- negative transfer;
- inconclusive.

## 8. Privacy Boundary

Debe impedir exposición de:

- identifiable tenant data;
- raw private metrics;
- confidential configuration.

## 9. Provenance

Debe conservar:

- source learning;
- abstraction process;
- target test;
- outcome.

## Regla crítica

El contrato debe separar source knowledge de target-specific validation.
