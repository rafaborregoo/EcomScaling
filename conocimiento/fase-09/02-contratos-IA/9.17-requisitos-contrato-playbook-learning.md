# 9.17 — Requisitos conceptuales para Playbook Learning Contract

## Identidad

Debe poder representar:

- playbook reference;
- version;
- objective;
- timestamp.

## Context

- tenant/context reference;
- maturity;
- business conditions;
- relevant moderators.

## Preconditions

Debe poder representar:

- required preconditions;
- precondition status;
- failed preconditions.

## Branching

- available branches;
- selected branch;
- branch rationale.

## Steps

Para cada step:

- step reference;
- version;
- expected role;
- status;
- execution fidelity;
- outcome evidence si existe.

## Sequence

- planned sequence;
- actual sequence;
- deviations.

## Dependencies

- upstream dependency;
- dependency status;
- impact of failure.

## Completion

- full;
- partial;
- aborted;
- skipped steps.

## Evaluation

Debe separar:

- playbook effectiveness;
- step effectiveness;
- sequence effectiveness;
- execution sensitivity.

## Learning

- critical step;
- redundant step;
- harmful step;
- new precondition;
- new dependency;
- branch update;
- version update.

## Regla

El contrato debe impedir inferir step-level effectiveness únicamente desde playbook-level outcome.
