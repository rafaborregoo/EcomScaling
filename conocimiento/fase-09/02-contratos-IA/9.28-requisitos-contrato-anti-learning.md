# 9.28 — Requisitos conceptuales de contrato para Anti-Learning

## Objetivo

Definir qué información debe representarse para prevenir conclusiones erróneas.

## 1. Evidence Validity

Debe representar:

- source quality;
- completeness;
- freshness;
- consistency;
- provenance;
- contamination.

## 2. Execution Fidelity

Debe distinguir:

- complete;
- partial;
- modified;
- failed;
- unknown.

## 3. Outcome Validity

Debe incluir:

- maturity;
- objective alignment;
- measurement validity;
- side effects.

## 4. Bias Signals

Debe poder representar:

- selection bias;
- survivorship;
- confirmation;
- feedback bias;
- aggregation risk;
- multiple testing.

## 5. Learning State

Debe permitir:

- candidate;
- inconclusive;
- quarantined;
- rejected;
- vetoed;
- validated.

## 6. Rejection

Debe incluir:

- reason;
- affected evidence;
- reviewer;
- timestamp conceptual;
- reversibility.

## 7. Falsification

Debe poder expresar:

- falsification criteria;
- counterexamples;
- contradiction evidence.

## 8. Confidence

Debe distinguir:

- evidence confidence;
- causal confidence;
- generalization confidence.

## 9. Provenance

Debe conservar:

- raw observation;
- transformations;
- metrics;
- execution;
- human feedback.

## Regla crítica

El contrato debe impedir que:

**observed outcome**

se interprete automáticamente como:

**validated learning**.
