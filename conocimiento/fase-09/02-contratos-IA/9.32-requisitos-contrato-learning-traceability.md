# 9.32 — Requisitos conceptuales de contrato para Learning Traceability

## Objetivo

Definir qué información debe poder representarse para reconstruir lineage y dependencias.

## 1. Trace Entity

Debe representar:

- entity id;
- entity type;
- version;
- status;
- tenant scope;
- effective period.

## 2. Trace Relation

Debe representar relaciones como:

- derived from;
- supports;
- contradicts;
- promoted from;
- supersedes;
- influenced;
- blocked by;
- generated outcome;
- reviewed by.

## 3. Provenance

Debe incluir:

- source;
- actor;
- tool;
- model version;
- context;
- transformation;
- time.

## 4. Upstream Links

Debe enlazar:

- observations;
- episodes;
- evidence;
- interventions;
- reviews.

## 5. Downstream Links

Debe enlazar:

- recommendations;
- decisions;
- playbooks;
- knowledge;
- promotions;
- outcomes.

## 6. Temporal State

Debe representar:

- valid from;
- valid until;
- decision-time state;
- current state.

## 7. Trace Completeness

Debe soportar:

- complete;
- partial;
- broken;
- inferred;
- unknown.

## 8. Transformation Record

Debe describir:

- input entity;
- transformation type;
- output entity;
- reason.

## 9. Impact Dependency

Debe permitir detectar qué objetos requieren review si cambia una pieza upstream.

## 10. Audit Metadata

Debe incluir:

- reviewer;
- change reason;
- rollback reference;
- lineage reference.

## Regla crítica

El contrato debe impedir entidades de knowledge críticas sin vínculo upstream suficiente.
