# 9.00 — Requisitos conceptuales del Learning Object

## Naturaleza de este artefacto

Este documento NO define un schema técnico.

Extrae del corpus únicamente los requisitos de información que deberían poder intercambiar los componentes responsables de experiencia, evidencia, atribución, aprendizaje y decisión futura.

La fuente establece explícitamente que en esta fase se define el modelo mental, no un schema.

---

## 1. Requisitos mínimos de una Experience

Una experiencia suficientemente interpretable debe poder conservar conceptualmente información sobre:

- contexto del ecommerce;
- problema o situación evaluada;
- decisión tomada;
- recomendación asociada, cuando exista;
- ejecución real;
- desviaciones de ejecución;
- entorno durante el periodo;
- ventana de observación;
- outcomes observados;
- métricas primarias;
- counter-metrics relevantes;
- baseline, expectativa o target disponible;
- cambios simultáneos relevantes.

La experiencia no debe reducirse a un único resultado.

---

## 2. Requisitos para describir ejecución

Cuando se evalúe una recomendación o estrategia, debe poder distinguirse:

- qué se pretendía ejecutar;
- qué se ejecutó realmente;
- si la ejecución fue fiel;
- si hubo modificaciones;
- si fue rechazada;
- si fue sustituida;
- si hubo fallos de herramientas, datos o permisos;
- si existieron incidencias o rollback.

El consumidor del contrato debe poder diferenciar calidad de recomendación, calidad de ejecución y calidad del outcome.

---

## 3. Requisitos de observación y comparación

El intercambio de información debería permitir responder:

- qué cambió;
- en qué magnitud;
- durante qué periodo;
- frente a qué baseline;
- frente a qué expectativa;
- frente a qué target;
- qué counter-metrics cambiaron;
- si el efecto fue de corto, medio o largo plazo.

Cuando no exista comparación válida, esta ausencia debe permanecer visible.

---

## 4. Requisitos de evidencia

Una evaluación de aprendizaje debe poder expresar conceptualmente:

- calidad de medición;
- integridad de datos;
- calidad de tracking;
- tamaño o suficiencia de muestra;
- duración de observación;
- varianza o ruido;
- consistencia de ejecución;
- estabilidad externa;
- información faltante;
- replicaciones previas;
- evidencia contradictoria.

No se exige convertir estos factores en una puntuación numérica artificial.

---

## 5. Requisitos de atribución

El intercambio entre componentes debe poder conservar:

- fuerza de atribución;
- razones que apoyan la atribución;
- confounders identificados;
- otras intervenciones concurrentes;
- cambios externos relevantes;
- explicaciones alternativas;
- mecanismo causal conocido, apoyado, plausible o especulativo;
- incertidumbres pendientes.

Una asociación temporal no debe representarse como causalidad confirmada.

---

## 6. Requisitos de Learning Object

Un aprendizaje útil debería poder responder conceptualmente a:

- ¿qué se aprendió?;
- ¿de qué evidencia procede?;
- ¿en qué contexto?;
- ¿bajo qué condiciones?;
- ¿con qué confianza?;
- ¿qué limitaciones existen?;
- ¿dónde puede aplicarse?;
- ¿dónde no debería asumirse aplicable?;
- ¿qué validez temporal tiene?;
- ¿qué impacto debería tener en futuras decisiones?;
- ¿qué experiencias y evidencias lo sustentan?

Estos requisitos constituyen responsabilidades semánticas, no campos obligatorios de una implementación concreta.

---

## 7. Requisitos de confianza

La confianza debe poder representarse sin pseudo-precisión.

Como mínimo debe existir capacidad para expresar:

- confianza actual;
- razones que la sostienen;
- factores que la reducen;
- cambio de confianza respecto de una creencia anterior;
- diferencia entre confianza direccional y confianza en la magnitud.

La confianza en un aprendizaje no debe confundirse con probabilidad de éxito de una futura acción.

---

## 8. Requisitos de generalización

Para transferir o ampliar un aprendizaje, debe existir información suficiente para comparar:

- business model;
- maturity;
- market;
- AOV;
- margin;
- purchase frequency;
- channel;
- category;
- traffic profile;
- customer type;
- brand strength;
- operational capacity.

El consumidor debe poder distinguir:

- tenant-specific learning;
- cohort-level learning;
- global learning.

La promoción de alcance no debe ser implícita.

---

## 9. Requisitos de trazabilidad

Todo aprendizaje relevante debe poder vincularse conceptualmente con:

`LEARNING → EVIDENCE → EXPERIENCES`

Debe ser posible identificar qué evidencia soporta una creencia y qué experiencias originaron esa evidencia.

Si una evidencia se invalida, los aprendizajes que dependan de ella deben ser localizables para reevaluación.

---

## 10. Requisitos de evolución del conocimiento

El sistema debe poder representar conceptualmente que una creencia nueva:

- refina;
- contextualiza;
- debilita;
- fortalece;
- contradice;
- coexiste con;
- sustituye;

una creencia anterior.

No debe asumirse un modelo de reemplazo destructivo simple.

---

## 11. Requisitos de resultado del proceso de aprendizaje

El resultado de una evaluación no siempre debe ser un nuevo aprendizaje.

Debe poder distinguirse conceptualmente entre:

- hypothesis;
- supported hypothesis;
- local learning;
- repeated pattern;
- validated pattern;
- knowledge candidate;
- inconclusive;
- no learning update.

---

## 12. Requisitos de impacto futuro

Un aprendizaje puede afectar futuras decisiones de formas diferentes:

- reinforce;
- weaken;
- contextualize;
- redirect;
- trigger exploration;
- generate caution;
- no immediate action.

No todo aprendizaje debe producir una acción inmediata.

---

## 13. Requisitos para evaluar Human Override

Cuando exista override humano, debe preservarse la diferencia entre:

- recomendación de IA;
- decisión humana;
- contexto adicional aportado por la persona;
- ejecución real;
- outcome.

La aprobación o el rechazo humano no deben convertirse por sí mismos en ground truth.

---

## 14. Requisitos para guardrails e incidentes

Cuando el aprendizaje se derive de ejecución o seguridad, debería poder incorporar evidencia sobre:

- prevented incidents;
- near misses;
- false positives;
- false negatives;
- tool failures;
- permission failures;
- data delays;
- misconfiguration;
- approval bottlenecks;
- rollback events.

---

## 15. Requisitos de temporalidad

Todo aprendizaje debe poder conservar conceptualmente una noción de vigencia.

Debe ser posible distinguir aprendizaje:

- vigente;
- debilitado;
- contextualizado;
- superseded;
- invalidated;
- pendiente de reevaluación por drift o cambio de contexto.

La fuente no prescribe un modelo técnico concreto para estos estados.
