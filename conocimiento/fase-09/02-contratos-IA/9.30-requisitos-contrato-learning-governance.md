# 9.30 — Requisitos conceptuales de contrato para Learning Governance

## Objetivo

Definir qué información debe intercambiarse para gobernar cambios de learning.

## 1. Governance Object

Debe representar:

- object id;
- object type;
- current state;
- scope;
- risk class;
- version.

## 2. Requested Action

Debe incluir:

- promote;
- degrade;
- supersede;
- invalidate;
- reactivate;
- expand scope;
- restrict scope;
- autonomy recommendation.

## 3. Required Authority

Debe representar:

- automatic;
- bounded automatic;
- human review;
- governance approval;
- prohibited.

## 4. Review State

Debe soportar:

- pending;
- under review;
- approved;
- rejected;
- deferred;
- escalated.

## 5. Evidence

Debe incluir:

- learning evidence;
- confidence;
- contradictions;
- provenance;
- risk;
- applicability.

## 6. Decision

Debe representar:

- outcome;
- rationale;
- actor;
- effective scope;
- effective date.

## 7. Override

Debe incluir:

- original proposal;
- override;
- reason;
- actor;
- later evaluation.

## 8. Audit Trail

Debe conservar:

- previous state;
- new state;
- timestamp conceptual;
- version;
- lineage.

## 9. Rollback

Debe permitir:

- revert;
- suspend;
- quarantine;
- restore previous state.

## Regla crítica

El contrato debe distinguir claramente:

**learning recommendation**

de:

**governance decision**.
