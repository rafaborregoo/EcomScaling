# 9.20 — Requisitos conceptuales de contrato para infraestructura y fricción operacional

## Objetivo

Definir qué información deben poder representar e intercambiar los componentes que evalúan readiness, ejecución, dependencias, infraestructura y fricción.

No define schemas ni implementación.

## 1. Intervención

Debe poder representarse:

- intervención;
- playbook;
- acción;
- objetivo;
- prioridad;
- owner;
- estado.

## 2. Readiness

Debe representar:

- acceso;
- datos;
- capacidad;
- herramienta;
- dependencias;
- approvals;
- rollback;
- observabilidad;
- readiness global;
- bloqueadores.

## 3. Dependencias

Debe poder expresar:

- componente dependiente;
- dependencia;
- criticidad;
- estado;
- disponibilidad;
- owner;
- condición de desbloqueo.

## 4. Infraestructura

Debe poder referenciar:

- sistema;
- herramienta;
- integración;
- API;
- pipeline;
- fuente de datos;
- estado operativo;
- fiabilidad;
- latencia;
- freshness;
- errores.

## 5. Fricción

Debe permitir clasificar:

- tipo;
- severidad;
- recurrencia;
- impacto;
- duración;
- causa;
- responsable;
- si es evitable o protectora.

## 6. Ejecución

Debe diferenciar:

- no iniciada;
- bloqueada;
- parcial;
- completada;
- fallida;
- revertida;
- abandonada.

## 7. Temporalidad

Debe representar:

- recommendation time;
- approval time;
- start time;
- completion time;
- validation time;
- outcome observation time.

## 8. Failure Attribution

Debe permitir distinguir:

- strategy failure;
- execution failure;
- infrastructure failure;
- process failure;
- capacity failure;
- timing failure;
- measurement failure.

## 9. Learning

Debe poder vincular:

- evidencia;
- fricción observada;
- bottleneck;
- reliability;
- outcome;
- confidence;
- contradicciones;
- applicability limits.

## 10. Provenance

Debe conservar el origen de:

- estados;
- errores;
- bloqueos;
- cambios de infraestructura;
- observaciones;
- decisiones humanas.

## 11. Versiones

Las conclusiones sobre infraestructura deben estar vinculadas a:

- herramienta;
- versión;
- integración;
- proceso;
- periodo temporal.

## 12. Regla crítica

El contrato debe impedir que:

**no execution**

sea interpretado automáticamente como:

**negative outcome**

o:

**bad recommendation**.
