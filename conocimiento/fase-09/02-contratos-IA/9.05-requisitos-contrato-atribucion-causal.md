# 9.05 — Requisitos conceptuales para contratos de atribución causal

## Objetivo

Definir qué información deberán poder intercambiar los componentes que evalúen causalidad, atribución e incrementalidad.

Este documento no define todavía JSON Schema, TypeScript, SQL ni implementación.

## Información mínima de entrada

El futuro contrato debe poder representar:

### Intervención

- identificador;
- tipo;
- descripción;
- fecha/hora de inicio;
- fecha/hora de fin si aplica;
- alcance;
- canal o superficie afectada;
- población o segmento expuesto.

### Outcome

- métrica evaluada;
- unidad;
- ventana temporal;
- nivel de agregación.

### Baseline

- periodo o referencia;
- metodología;
- valor observado;
- calidad o limitaciones.

### Contrafactual

- método de estimación;
- población/control utilizado;
- periodo comparable;
- supuestos;
- limitaciones.

### Evidencia

- fuentes;
- métricas relacionadas;
- diseño de medición;
- observaciones relevantes.

## Información mínima de salida

El contrato futuro debe poder representar:

- cambio observado;
- efecto incremental estimado, si existe;
- dirección del efecto;
- magnitud;
- rango o incertidumbre;
- nivel de evidencia;
- clasificación de la afirmación:
  - descriptiva;
  - asociativa;
  - causal plausible;
  - causal respaldada;
  - incremental cuantificada;
- explicación resumida;
- alternativas plausibles;
- caveats;
- recomendación resultante.

## Trazabilidad

Toda conclusión causal debe poder referenciar:

- intervención;
- outcome;
- baseline;
- contrafactual;
- fuentes;
- periodo analizado;
- método;
- versión del análisis.

## Incertidumbre

El contrato no debe limitarse a un booleano:

```text
causal = true/false
```

Debe permitir expresar grados de evidencia e incertidumbre.

## Separación atribución / incrementalidad

Debe ser posible representar por separado:

- conversiones atribuidas;
- revenue atribuido;
- conversiones incrementales estimadas;
- revenue incremental estimado.

No deben compartir un único campo semánticamente ambiguo.

## No inferir ausencia de datos

Si falta un contrafactual o la evidencia es insuficiente, la salida debe poder expresar:

```text
evidence_insufficient
```

o equivalente conceptual.

No debe forzarse una cifra causal.

## Compatibilidad futura

Estos requisitos deberán ser reutilizables por:

- experimentation;
- post-intervention evaluation;
- channel analysis;
- media scaling;
- CRO;
- CRM;
- pricing;
- promotion analysis;
- learning system.
