# 9.09 — Requisitos conceptuales para Learning Confidence Contract

## Objetivo

Definir qué información deberá poder intercambiar un futuro contrato de confianza de aprendizaje.

No define todavía JSON Schema, TypeScript, SQL ni implementación.

## Identidad

Debe poder representar:

- learning reference;
- claim reference;
- confidence assessment reference;
- assessment timestamp;
- version.

## Confidence

- confidence level;
- rationale;
- previous confidence;
- direction of change.

## Drivers

Debe poder referenciar:

- evidence quality;
- execution fidelity;
- attribution strength;
- replication status;
- context stability;
- contradictory evidence;
- outcome maturity.

## Constraints

Debe poder expresar:

- confidence ceiling;
- unresolved uncertainty;
- missing evidence;
- caveats.

## Provenance

Debe trazarse hasta:

- supporting evidence;
- contradictory evidence;
- contexts;
- interventions;
- outcomes.

## History

Debe ser posible reconstruir:

```text
confidence at T0
→ reason for change
→ confidence at T1
```

## Regla

El contrato no debe representar confidence como probabilidad numérica salvo que exista un método cuantitativo explícitamente calibrado que justifique esa interpretación.
