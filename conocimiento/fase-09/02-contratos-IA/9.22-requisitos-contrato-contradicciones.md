# 9.22 — Requisitos conceptuales de contrato para contradicciones entre aprendizajes

## Objetivo

Definir qué información debe poder representarse e intercambiarse para detectar y gestionar contradicciones.

## 1. Learning Claim

Debe poder representarse:

- claim id;
- statement;
- scope;
- context;
- intervention;
- outcome;
- direction;
- magnitude;
- confidence;
- evidence strength;
- temporal validity;
- provenance;
- version.

## 2. Contradiction Relation

Debe poder expresar:

- claim A;
- claim B;
- overlap;
- type;
- severity;
- contradiction scope;
- detection time.

## 3. Contradiction Type

Debe permitir clasificar:

- direct;
- contextual;
- temporal;
- metric;
- causal;
- evidence;
- granularity;
- global-vs-tenant.

## 4. Evidence Comparison

Debe poder comparar:

- support;
- coverage;
- independence;
- quality;
- recency;
- attribution;
- uncertainty.

## 5. Resolution State

Debe representar:

- apparent;
- unresolved;
- contextualized;
- fragmented;
- prioritized;
- superseded;
- invalidated;
- preserved conflict.

## 6. Resolution Rationale

Debe incluir:

- evidence used;
- reason;
- human review;
- limits;
- uncertainty;
- effective date.

## 7. Supersession

Debe mantener:

- previous claim;
- new claim;
- reason;
- version chain;
- effective scope.

## 8. Exceptions

Debe poder expresar:

- tenant exception;
- cohort exception;
- channel exception;
- temporal exception;
- metric exception.

## 9. Provenance

Nunca debe perderse:

- source;
- intervention;
- experiment;
- outcome;
- human decision;
- model version.

## Regla crítica

El contrato debe impedir el silent overwrite de claims contradictorios.
