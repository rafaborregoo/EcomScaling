# 9.07 — Requisitos conceptuales para contratos de evidencia

## Objetivo

Definir qué debe poder representar un futuro Evidence Contract sin imponer todavía un schema técnico.

## Identidad de evidencia

- evidence id;
- source;
- evidence type;
- design type;
- timestamp / period;
- provenance.

## Diseño

Debe poder representar:

- treatment;
- control;
- assignment method;
- unit of analysis;
- population;
- exposure;
- duration.

## Outcome

- primary outcome;
- secondary outcomes;
- unit;
- baseline;
- observed result.

## Estimación

- effect direction;
- effect magnitude;
- uncertainty;
- materiality.

## Calidad

- measurement quality;
- contamination;
- confounding;
- sample adequacy;
- consistency;
- replication status.

## Evaluación

- evidence strength;
- internal validity;
- external validity;
- applicability;
- caveats.

## Relación con learning

Debe poder trazarse:

```text
learning
→ supporting evidence
```

y también:

```text
contradictory evidence
→ affected learning
```

## Regla

El contrato no debe reducir fuerza de evidencia a un único booleano `valid=true/false`.
