# 9.18 — Requisitos conceptuales para Calibration Contract

## Identidad

Debe poder representar:

- benchmark / threshold / guardrail reference;
- version;
- context;
- effective period.

## Decision Boundary

- threshold;
- monitored signal;
- trigger condition;
- resulting action.

## Outcome Classification

Debe poder vincular:

```text
TRUE_POSITIVE
FALSE_POSITIVE
TRUE_NEGATIVE
FALSE_NEGATIVE
NEAR_MISS
PREVENTED_INCIDENT
```

cuando exista evidencia suficiente.

## Cost and Severity

- operational friction;
- review burden;
- risk exposure;
- severity;
- reversibility.

## Benchmark Validity

- source;
- cohort;
- metric definition;
- comparability;
- recency;
- confidence.

## Calibration Assessment

Debe poder representar:

```text
TOO_STRICT
WELL_CALIBRATED
TOO_PERMISSIVE
UNCERTAIN
```

## Proposed Change

Conceptualmente:

```text
TIGHTEN
RELAX
CONTEXTUALIZE
ESCALATE
DE_ESCALATE
RETIRE
ADD
NO_CHANGE
```

## Governance

Debe indicar:

- recommendation only;
- review required;
- approved/rejected;
- effective version.

## Regla

El contrato no debe permitir que un learning modifique directamente un guardrail crítico sin governance.
