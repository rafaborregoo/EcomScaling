# 9.13 — Requisitos conceptuales para Incident Learning Contract

## Identidad

Debe poder representar:

- incident reference;
- tenant / scope reference;
- timeline;
- status.

## Classification

- execution error;
- guardrail failure;
- incident;
- near miss;
- suspected incident;
- false alarm.

## Expected vs Actual

- expected action/state;
- actual action/state;
- deviation.

## Causal analysis

- trigger;
- root cause;
- contributing factors;
- confidence.

## Impact

- severity;
- blast radius;
- affected systems;
- affected outcomes;
- reversibility.

## Response

- detection;
- detection latency;
- containment;
- rollback;
- recovery.

## Residuals

- residual effects;
- contaminated data period;
- unresolved risks.

## Learning

- corrective learning;
- preventive learning;
- autonomy implications;
- policy implications;
- runtime implications.

## Recurrence

Debe poder vincular eventos similares previos.

## Regla

El contrato debe mantener separadas la calidad de la estrategia, la calidad de ejecución y el impacto final.
