# 9.37 — Requisitos conceptuales de contrato para privacidad, aislamiento y aprendizaje

## Objetivo

Definir qué información debe representarse para controlar privacy boundaries.

## 1. Tenant Scope

Debe incluir:

- tenant id;
- ownership;
- permitted scopes;
- cross-tenant eligibility.

## 2. Sensitivity

Debe representar:

- public;
- internal;
- confidential;
- sensitive;
- personal-data-related;
- restricted.

## 3. Knowledge Privacy State

Debe permitir:

- tenant-private;
- cohort-aggregated;
- global-curated;
- non-transferable;
- restricted.

## 4. Transfer Eligibility

Debe incluir:

- allowed;
- blocked;
- requires abstraction;
- requires aggregation;
- requires review.

## 5. Aggregation State

Debe representar:

- source count;
- cohort size;
- re-identification risk;
- aggregation method conceptual.

## 6. Access

Debe incluir:

- role;
- purpose;
- component;
- tenant;
- knowledge layer.

## 7. Retention

Debe representar:

- retention class;
- expiry;
- deletion requirement;
- audit retention.

## 8. Derived Dependency

Debe enlazar:

- source data;
- embedding;
- summary;
- learning;
- knowledge object.

## 9. Provider Boundary

Debe representar conceptualmente:

- external processor;
- data category;
- retention/training constraints;
- allowed processing purpose.

## 10. Provenance

Debe conservar origen sin obligar a exponer contenido sensible.

## Regla crítica

El contrato debe hacer imposible tratar knowledge tenant-private como global-curated sin una transición explícita.
