# Fase 03 · D03 — Guardrails de madurez

## Propósito

Reglas estructurales que no deben depender únicamente del RAG.

---

1. **REVENUE ≠ MATURITY.**
2. **PERFORMANCE ≠ MATURITY.**
3. **USING TOOL ≠ HAVING CAPABILITY.**
4. **AUTOMATION ≠ MATURITY.**
5. **TEAM SIZE ≠ MATURITY.**
6. **DOCUMENTATION ≠ MATURITY.**
7. **STATE ≠ STAGE.**
8. **MISSING ADVANCED CAPABILITY ≠ PROBLEM.**
9. **No penalizar simplicidad si satisface correctamente la necesidad.**
10. **No premiar complejidad por sí misma.**
11. **No usar una puntuación vanity sin interpretación diagnóstica.**
12. **No comparar empresas solo entre sí; comparar capability actual vs capability requerida.**
13. **No convertir un current issue en maturity regression sin evidencia estructural persistente.**
14. **No asumir maturity alta porque exista un dashboard, ERP, Klaviyo, GA4, IA o automatización.**
15. **No asignar stage alto basándose únicamente en user claims.**
16. **Priorizar observed system behavior sobre documentación y autopercepción.**
17. **No asumir que una asimetría entre capabilities es problema si no crea dependencia o riesgo.**
18. **No confundir healthy specialization con dangerous imbalance.**
19. **No confundir maturity bottleneck con prioridad actual.**
20. **No considerar capacidad madura si existe pero no se usa, no se mide o no cambia decisiones.**
21. **No considerar forecasting maduro si no se mide accuracy ni se analizan errores.**
22. **No usar herramientas externas o frameworks como verdad específica del tenant.**
23. **No dejar que heurísticas contradigan evidencia interna más fuerte.**
24. **No escalar spend, markets, team o inventory sin capacidades base suficientes.**
25. **No exigir capacidades enterprise a un negocio cuya complejidad no las necesita.**
26. **No confundir temporal outage con structural regression.**
27. **No sobrescribir stage histórico sin evidencia de cambio real.**
28. **No tratar confidence más alta como aumento automático de maturity.**
29. **No clasificar como madura una capacidad sin ownership suficiente cuando este sea necesario.**
30. **No clasificar como adaptive una capability sin capacidad real de detectar, aprender y ajustar.**
