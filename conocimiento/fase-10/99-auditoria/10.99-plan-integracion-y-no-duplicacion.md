## Dependencia crítica: pipeline RAG

La auditoría detectó:

- `00-corpus-maestro` está permitido por el script aunque el README diga que solo `01-rag-produccion` debe indexarse;
- el script salta documentos con el mismo título aunque el contenido haya cambiado;
- el checksum existe pero no gobierna la sincronización;
- borrar un `.md` no archiva el documento correspondiente;
- no existe hash por chunk;
- no existe sincronización repo→BD real.

### Regla de publicación

NO reindexar esta fase hasta corregir o encapsular el pipeline de sincronización.

Como mínimo:

1. solo `01-rag-produccion` debe poder publicarse como RAG de producción salvo decisión explícita contraria;
2. un documento modificado debe actualizarse mediante PUT o flujo equivalente, no saltarse por título;
3. un documento eliminado o retirado debe archivarse;
4. el checksum debe participar en la decisión `unchanged/update/create/archive`;
5. la sincronización debe ser idempotente;
6. debe existir `--dry-run` o equivalente antes de aplicar cambios;
7. el proceso debe producir un manifiesto de:
   - created
   - updated
   - unchanged
   - archived
   - failed

## Criterio de no duplicación

No crear un nuevo documento si:

- el concepto ya está completo en una fuente canónica;
- solo cambia el nombre;
- la diferencia es puramente de canal y puede resolverse con un enlace/adapter;
- el contenido pertenece a runtime/configuración y no a conocimiento.

Crear un nuevo documento solo cuando:

- resuelva un hueco de recuperación real;
- establezca una interfaz entre dominios;
- introduzca una política transversal inexistente;
- formalice un contrato que antes estaba fragmentado.
