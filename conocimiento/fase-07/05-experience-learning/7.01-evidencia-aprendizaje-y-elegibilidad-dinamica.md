# FASE 7.1 — Evidencia, aprendizaje y elegibilidad dinámica

## Propósito

Este artefacto contiene los conceptos del bloque 7.1 que pertenecen a aprendizaje operacional y actualización basada en experiencia.

No describe conocimiento experto estático del ecommerce.

Describe cómo nueva evidencia, experimentos y cambios del sistema pueden modificar la elegibilidad de una intervención.

---

## 1. La elegibilidad cambia con la experiencia

La elegibilidad no es permanente.

Puede cambiar por:

- nueva evidencia;
- cambios de stock;
- cambios de cash;
- performance;
- madurez;
- capacidad;
- resultados de experimentos;
- cambios del mercado;
- calidad de datos;
- cambios operativos.

Una intervención que era elegible puede dejar de serlo cuando cambia una condición crítica.

---

## 2. Tipos de evidencia

### Evidencia directa

Observa el mecanismo concreto.

Ejemplo:

```text
checkout errors ↑
checkout completion ↓
```

Aporta soporte fuerte para un fix del checkout.

### Evidencia indirecta

Existen señales compatibles, pero el mecanismo no está completamente confirmado.

Ejemplo:

```text
CTR ↓
frequency ↑
creative age ↑
```

Puede apoyar una hipótesis de fatiga creativa con menor certeza.

### Evidencia débil

Una métrica agregada aislada no permite distinguir causas.

Ejemplo:

```text
CAC ↑
```

sin descomposición adicional.

La experiencia-learning debe preservar esta diferencia porque no todo dato tiene el mismo valor probatorio.

---

## 3. Evidencia disconfirmatoria

El sistema debe aprender también de señales que contradicen una hipótesis.

Ejemplo:

Hipótesis:

```text
creative fatigue
```

pero aparecen:

```text
CTR estable
frequency baja
creative diversity alta
```

Estas señales reducen la justificación de un `creative refresh` como solución al problema concreto.

El aprendizaje no debe acumular solo evidencia favorable.

---

## 4. Value of Information

Una intervención puede generar valor aunque no busque una mejora inmediata.

Puede ser elegible por reducir incertidumbre cuando:

- la incertidumbre afecta a decisiones materiales;
- el aprendizaje obtenido cambiará decisiones futuras;
- obtener la información tiene bajo coste;
- el test es reversible;
- la variable puede aislarse.

El outcome relevante puede ser:

```text
better decision information
```

y no necesariamente un uplift inmediato.

---

## 5. Gather evidence como acción de aprendizaje

Cuando distintas causas continúan siendo plausibles, la acción más útil puede ser obtener evidencia.

Ejemplo conceptual:

```text
CAC deteriorándose
```

sin saber si viene de:

```text
CPM
CTR
CVR
AOV
```

La experiencia útil no es “probar una solución cualquiera”, sino descomponer el sistema para reducir incertidumbre.

---

## 6. Preservar señal

El sistema debe proteger la capacidad de aprender.

Si existe una hipótesis activa, introducir múltiples cambios simultáneos puede impedir atribución.

Ejemplo:

```text
new landing
+
new price
+
new bundle
+
new traffic source
```

Si el resultado mejora, no se sabe qué cambio lo causó.

La learning layer debe tratar la interpretabilidad del outcome como un activo.

---

## 7. Experiment collision

Dos intervenciones pueden ser individualmente razonables y, sin embargo, producir una mala experiencia de aprendizaje cuando se ejecutan simultáneamente.

La elegibilidad debe poder disminuir temporalmente para proteger un experimento activo.

La experiencia histórica debería poder registrar que una intervención fue pospuesta por interferencia, no porque la estrategia fuese intrínsecamente mala.

---

## 8. Condiciones para que un test produzca aprendizaje

Un test es útil cuando:

- existe hipótesis relevante;
- la variable puede aislarse;
- hay volumen suficiente;
- el coste es razonable;
- el resultado puede interpretarse.

Un test puede producir poca o ninguna experiencia útil cuando:

- el volumen es insuficiente;
- hay demasiadas variables inseparables;
- el tiempo de aprendizaje es excesivo;
- el impacto es irrelevante;
- el bug ya está confirmado y no requiere experimento.

---

## 9. Calidad de datos como calidad de experiencia

Una experiencia basada en medición defectuosa no debe tener el mismo peso que una experiencia basada en datos fiables.

Una discrepancia grande de tracking puede invalidar la interpretación de CAC, ROAS u otros outcomes.

Conceptualmente:

```text
poor measurement
→ lower evidence quality
→ lower confidence in eligibility
```

---

## 10. Recencia de evidencia

La experiencia envejece cuando cambia el sistema.

Una auditoría antigua puede perder capacidad predictiva tras:

- nuevo storefront;
- nuevo checkout;
- nuevo pricing;
- cambios sustanciales de canal;
- cambios operativos.

Por tanto, la learning layer debería preservar el contexto temporal de la evidencia para no tratar información obsoleta como equivalente a evidencia reciente.

El bloque no define una fórmula de decay.

---

## 11. Segmentación de outcomes

Una experiencia agregada puede ocultar efectos heterogéneos.

Ejemplo:

```text
CVR total estable
```

pero:

```text
new customer CVR ↓
returning customer CVR ↑
```

El aprendizaje útil puede requerir resultados segmentados.

Una conclusión global no debe promoverse automáticamente si existen subgrupos con comportamiento opuesto.

---

## 12. Reversibilidad y experimentación

Las acciones reversibles tienen mayor valor como instrumentos de aprendizaje porque permiten:

- reducir downside;
- explorar hipótesis;
- acotar cambios;
- volver atrás con menor coste.

Esto permite aprender con menos evidencia previa que en intervenciones irreversibles o estructurales.

---

## 13. Aprendizaje frente a mejora inmediata

Una intervención puede tener dos tipos de valor:

### Valor operativo

Mejora directamente el resultado.

### Valor informacional

Reduce incertidumbre para decisiones futuras.

Ambos deben distinguirse para no infravalorar tests, investigación o recopilación de evidencia.

---

## 14. Reevaluación posterior a outcomes

Después de una acción o experimento, nueva evidencia puede:

- aumentar elegibilidad de una intervención;
- reducirla;
- desbloquear una dependencia;
- revelar un hard blocker;
- convertir una acción prematura en elegible;
- convertir una acción elegible en inapropiada.

El sistema de aprendizaje debe permitir que outcomes posteriores modifiquen el conjunto de candidatos.

---

## 15. Lo que este bloque no define

La fuente no especifica:

- schema de `Experience`;
- IDs;
- estructura de outcome;
- confidence numérica;
- función de actualización;
- promotion thresholds;
- knowledge promotion;
- decay cuantitativo;
- memoria persistente;
- algoritmo de generalización;
- aprendizaje entre tenants;
- evaluación causal formal.

Esos elementos requieren una fase posterior de contratos e infraestructura.
